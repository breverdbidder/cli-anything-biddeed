## Findings (not fixed — out of scope)

1. **`ff_batch_leads.assessed_value` was itself mislabeled pre-fix**: it held
   `1502280.00` — the parcel's *Just Value* (`jv`), not an assessed value —
   with `market_value` left `NULL`. This is a distinct, pre-existing bug in
   whatever ingested that row (outside this issue's data path), not
   something this session's fix touches beyond overwriting both fields with
   the now-correct PA figures for this one case.
2. **`ff_batch_leads` has no dedicated `land_value`/`building_value`/
   `coverage_a` columns** — the corrected figures for those went into
   `field_provenance_json` instead. If the Investor Property FF
   (`render_ff_9buyer_20260827.py`) is ever pointed back at this row, verify
   it actually reads that JSON key shape before assuming the fix propagates
   there.
3. **`fl_parcel_appraiser_accounts` is seeded with exactly one row** (this
   parcel only). Nothing in this session builds an automated way to
   discover other Martin account numbers — future Martin FFs still fall
   back to the FOLIO/search-results `parcel_url_template` until more
   accounts are found and inserted by hand or a future resolver script.
