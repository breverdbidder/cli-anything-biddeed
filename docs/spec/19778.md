## Deviations from spec

Flagged UNKNOWN rather than estimated.
3. **#19761 comment thread not exhaustively fetched.** Only the last 3 comments were pulled (consistent with the same method used for #19766/#19752); no SQL-verification block was visible in that slice. Flagged UNKNOWN rather than asserting one doesn't exist anywhere in the thread.
4. **YouTube secret check scoped to 8 repos, not all 307.** Checking `gh secret list` (a slow, rate-limited call) against all 307 repos was judged disproportionate to a "names only, report what exists" ask. The 8 checked are the ones plausibly running video/content pipelines per the repo inventory in §1.

- **`social_content_queue` (684 rows) also has no live drain** — no cron job or workflow references it. It was populated at some point but nothing currently consumes it.
- **No YouTube channel or API credential exists anywhere checked** (repo, vault, unified_context, 8-repo secret scan) — `zonewise-content-engine` targets YouTube as a publish channel but has no credential to do so.
- **`winnerdata` schema is not exposed to PostgREST via the service_role key** (confirmed permission gap at the DB level) — any future pipeline reading/writing `winnerdata.*` via the JS/PostgREST client (not direct SQL) will hit `42501`. Worth a `GRANT USAGE ON SCHEMA winnerdata TO service_role` follow-up if PostgREST access to that schema is ever needed (not done here — DDL is out of this issue's scope).
- **`biddeed-reels-daily.yml` / `biddeed-reels-presale.yml` are `workflow_dispatch`-only**, no cron — the 23-reel pipeline currently requires a manual trigger, consistent with M1 (nothing auto-sends).
