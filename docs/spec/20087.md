## Intent reference

## What was built
One-line copy fix plus a smoke-test regression gate, exactly as scoped.

**cli-anything-biddeed** (commits 91c9cdc9, 6e59e8db):
- `src/worker.js` — the `.reel-view-link` anchor inside the `/reels/:code` gallery card
  template (`buildReelCardHtml`) changed from `View property &rarr;` to
  `See this deal &rarr;`. No other text, styling, or `href` touched — the `viewHref`
  computation (routing through `/r/{code}`) was left exactly as-is. The
  `.reel-cta-overlay` anchor a few lines above already said `See this deal &rarr;`
  (from the prior #19779/#20084 CTA work) — the two links now match, closing the M9
  label-parity gap.
- Repo-wide grep for human-facing `View property` / `View Property` across
  `*.js *.ts *.html *.htm *.jsx *.tsx`, excluding `node_modules` and the historical
  `docs/spec/19796.md` record (a point-in-time snapshot of prior output, not live
  code) — zero remaining occurrences. `src/worker.js:6022` was the only live surface
  carrying the retired label.
- `.github/workflows/deploy-worker.yml` — new smoke-test step "Smoke test — reel CTA
  label parity (#20087)" added to the existing #20053-gate deploy job, after the
  #20058 brand check. Curls `/reels/O7EPH7` and `/reels/F5oeMD`, asserts exactly 2x
  "See this deal" and 0x "View property" per page; fails the deploy (not a warning)
  on any miss.
- Follow-up commit 6e59e8db fixed a bug in that same smoke-test step found while
  watching the first CI run (34080413808) fail: `grep -o "View property" | wc -l`
  exits 1 when there are zero matches (the passing case), and under
  `set -euo pipefail` that aborted the script before the FAIL/pass logic ever ran —
  so the gate was failing for the wrong reason (a script bug, not a label
  regression). Fixed with `|| true` on both count assignments, matching the
  `|| true` pattern already used on the `curl` line above it in the same file.

No migrations. No schema changes. No RPCs touched. No spend.
