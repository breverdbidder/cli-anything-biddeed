## Deviations from intent
- The issue said "run the generalized AcclaimWeb `name_lookup()` against Highlands' instance."
  That function no longer works for Highlands, confirmed two independent ways: (1) its results-grid
  endpoint was renamed `GridResults` → `GetSearchResults` (fixed generically in
  `pre_auction_lien_harvest.py`, benefits any future Highlands `case_lookup()` call); (2) even
  pointed at the renamed endpoint, Highlands' real name-search form uses different field names
  (`Name`/`NameMatchingMode`) and a single-step submit flow with no name-disambiguation popup,
  unlike Duval's Kendo treeview flow `name_lookup()` implements. Reverse-engineering a second
  AcclaimWeb build's exact field contract into the shared class risked regressing Duval/Santa Rosa
  for a one-time 2-case pull, so this session drove the real site with Playwright instead (same
  data, same site, same disclaimer — just browser automation instead of raw HTTP replay) and fed
  the real results into the unmodified shared classifier. Disclosed here rather than silently
  presented as "ran name_lookup()".
- Added a search-audit `title_defects` marker (not requested verbatim in the issue, but required by
  its own verification clause: "No report with a false 'insufficient coverage' message on a case
  that was actually searched"). Without it, `lien-survival.js`'s `checkSearchedClean()` — which
  only recognizes a `title_defects` row as proof a search ran — would render the false message for
  both Highlands cases, since Ch.197 tax-deed cases never produce a JUDGMENT/LIS-PENDENS row via
  the normal `case_lookup()` path (they're not docketed there at all). First attempt at the wording
  had a live bug (a stray `(s)` in "document(s)" and a parenthesized case number both preceded the
  intended source tag, so `checkSearchedClean()`'s first-paren-match regex extracted `"s"` instead
  of the real source) — caught by re-running `lien-survival.js classify()` directly against the
  freshly-inserted rows before treating the task as done, fixed, and re-verified.
