## What was built

### Part 1 — File importer (VERIFIED)
- **`workers/everest-bank-engine/src/csvImport.ts`** — Wells Fargo CSV parser (no header row,
  `Date,Amount,*,*,Description`), hand-written quoted-field-aware line splitter (no vendored
  dependency).
- **`workers/everest-bank-engine/src/ofxImport.ts`** — OFX 1.x SGML / 2.x XML parser via a
  small regex-based tag extractor (`<STMTTRN>` blocks; leaf-tag values read up to the next `<`,
  which works for both SGML's unclosed leaf tags and XML's closed ones).
- **`workers/everest-bank-engine/src/importUtils.ts`** — shared `ParsedTxn` type +
  `sha256Hex`/`fallbackTransactionId` (Web Crypto `crypto.subtle.digest`, no dependency).
- **`workers/everest-bank-engine/src/fileImport.ts`** — orchestration: format auto-detect,
  parse, negate sign into this Worker's storage convention (single point of negation, see
  README), upsert connection/account/transactions.
- **`workers/everest-bank-engine/src/importPage.ts`** — `GET /import` HTML upload form (entity
  dropdown from `finance.entities`, mask/account-label/file inputs, JS `fetch` submit — mirrors
  `linkPage.ts`'s pattern of a public page whose embedded key drives a gated POST).
- **`src/index.ts`** — `GET /import` (public, like `GET /link`) + `POST /import` (gated inline,
  since Hono's `app.use("/import", ...)` would gate both methods on the exact path unlike the
  `/link/*` wildcard).
- **`supabase/migrations/20260902m_bank_file_simplefin_rpc.sql`** — 4 new `SECURITY DEFINER`
  RPCs in `public`, `EXECUTE` granted to `service_role` only (verified live, `anon` denied):
  `bank_engine_upsert_connection_status` (generic connection upsert with an explicit `status`,
  distinct from #19737's Plaid-only `bank_engine_upsert_connection` which hardcodes
  `status='active'`), `bank_engine_import_transactions` (transaction upsert that never touches
  `bank_connections.cursor` — a Plaid-cursor-sync concept that doesn't apply here),
  `bank_engine_list_entities` (read-only, powers the `/import` dropdown — `service_role` has no
  `finance` schema `USAGE`, same reason #19737's RPC layer exists at all),
  `bank_engine_simplefin_default_entity` (cron entity attribution, see Part 2). Applied live via
  Management API (`mgmt_sql.py`) — direct psql confirmed dead again this session (decision_log
  169/205/287).

### Part 2 — SimpleFIN Bridge connector (built, BLOCKED on live activation)
- **`workers/everest-bank-engine/src/simplefin.ts`** — `claimSetupToken` (base64-decode setup
  token → claim URL → `POST` → Basic-Auth access URL → stored **only** in vault as
  `simplefin_access_url`), `syncSimplefin` (Basic Auth header built from the access URL's
  userinfo, `GET {access_url}/accounts?start-date=&end-date=`, upserts per-account connections
  with `status='simplefin'`), `syncSimplefinCron` (6h-tick entry point, reads back the entity
  code from the most recent `status='simplefin'` connection rather than requiring a second
  place to store it).
- **`src/index.ts`** — `POST /simplefin/claim`, `POST /simplefin/sync`, both gated by
  `app.use("/simplefin/*", ...)` (same pattern as `/link/*`). `scheduled()` handler extended to
  also call `syncSimplefinCron` on the existing 6h tick — **no new `[triggers]` cron entry**,
  per the issue's "cron every 6h alongside Plaid sync."

## Deviations from intent
1. **Reused `finance.bank_connections`/`bank_accounts`/`bank_transactions`'s existing
   `plaid_item_id`/`plaid_account_id`/`plaid_transaction_id` columns for file/SimpleFIN rows**,
   exactly as the issue itself specified (`plaid_item_id = 'file:'||mask`, etc.) — no schema
   change needed. Flagging only because it means these column names are now genuinely
   source-agnostic (Plaid, file import, and SimpleFIN all write through them); a future reader
   should not assume `plaid_item_id LIKE 'plaid_%'`.
2. **`CFO_AGENT_SHARED_SECRET` could not be read back this session** (GitHub Actions secrets are
   write-only, same finding as #19737/#19738 — no sanctioned vault accessor covers a name
   outside the `cli_anything_*`/`everest_*_pat` allow-list). Per `CC_META_PROMPT.md`
   CREDENTIAL HANDLING ("run any task that needs a credential INSIDE the GHA runner... never
   from a chat session"), added a temporary diagnostic workflow
   (`.github/workflows/tmp-bank-import-test-19749.yml`) that ran the real authenticated
   `POST /import`/`POST /simplefin/*` calls with the secret masked at execution, captured the
   results, then was deleted in the same session (commits `612ae835` add, `52fc2180`/`d632b080`
   iterate, `4bf644f0` remove) — same "added, used, removed" pattern #19738 used for its
   `/api/recon/*` live test. This also means Part 1's DoD item 1 evidence is a synthetic
   WF-format fixture (explicitly tagged as such), not a real Ariel-uploaded file, since none was
   available in `GET /import`'s inbox this session — the exact fallback the issue itself
   anticipated ("or a synthetic file in WF format tagged source=fixture -- say so plainly").
3. **`bridge.simplefin.org`/`beta-bridge.simplefin.org` blocked by Cloudflare bot management —
   confirmed genuinely external, not a credential problem.** Tested the identical `POST
   /simplefin/claim/demo` request from three distinct network origins: (a) this session's own
   sandbox (`curl`, browser UA, still 403/redirect-then-403), (b) a GitHub Actions runner
   (different IP/ASN, still returns an HTML page, `HTTP 200` status but Cloudflare
   "Forbidden - SimpleFIN Bridge" challenge body), (c) the deployed Cloudflare Worker's own
   server-side `fetch()` (Cloudflare-edge-to-edge traffic — same 200-with-HTML-challenge
   result, confirmed via a redacted-preview diagnostic added to `simplefin.ts`'s BLOCKED path:
   `"got: <!doctype ht...(5018 chars)...tml>"`). All three are non-interactive HTTP clients
   that cannot execute Cloudflare's JS challenge — this is a demo-endpoint bot-protection wall,
   not something any of the sanctioned credential fallbacks (Management API, PostgREST, GHA
   runner) can route around. Per the runtime's own instruction ("Only stop early for a genuine
   data ceiling... document it inline"), this is exactly that: the code is implemented per the
   published protocol spec, fails safe (rejects the bad response, never stores a placeholder in
   vault), and is ready to work the moment a real setup token (from an actual bank's SimpleFIN
   Bridge deployment, not the shared public demo) is supplied — those are typically not behind
   the same public bot-challenge since they're reached via each bank's own bridge, not
   `bridge.simplefin.org`'s heavily-abused shared demo path.
4. **Kept the redacted-preview diagnostic in `simplefin.ts`'s BLOCKED error path** rather than
   reverting it after use — it is a small (~3 line), permanently-safe addition (bounded,
   redacted, only fires on the already-invalid-response branch) that will help whoever activates
   this with Ariel's real token diagnose a similar failure mode without needing another
   temporary workflow.

## Negative test result
- `POST /import` and `POST /simplefin/sync` with no/wrong `X-CFO-Secret`: both return `401`
  (added to `deploy-bank-engine.yml`'s existing security-gate step, run live on every deploy —
  confirmed green on this session's deploy, run
  [33676495148](https://github.com/breverdbidder/cli-anything-biddeed/actions/runs/33676495148)).
- `POST /simplefin/claim` with a bad/unreachable response: correctly returns `BLOCKED` (`422`),
  never writes a placeholder to `vault.secrets`.
- `POST /simplefin/sync` before any successful claim: correctly returns `SKIPPED` (`409`),
  confirmed live (`{"status":"SKIPPED","error":"no simplefin_access_url in vault -- call POST
  /simplefin/claim first"}`).
- Malformed CSV/OFX rows (short row / missing DTPOSTED-TRNAMT) are skipped per-row rather than
  failing the whole file — implemented in `csvImport.ts`/`ofxImport.ts`, not independently
  live-tested with an intentionally-malformed fixture this session (flagged, not claimed).

## Findings (not the task, but worth more than the task)
1. **SimpleFIN's public demo bridge is unreachable from any non-browser client as of this
   session** (2026-09-02) — this is worth knowing for whoever picks up real SimpleFIN
   activation: don't spend time re-diagnosing the demo path; go straight to a real bank's own
   SimpleFIN Bridge setup token from Ariel, since real bank bridges are generally not served
   from the same heavily-bot-protected shared demo host.
2. **`finance.bank_connections.plaid_item_id`/`bank_accounts.plaid_account_id` are now a
   3-way-shared namespace** (`plaid:...` implicit for real Plaid item ids, `file:...`,
   `simplefin:...`). No collision risk today (distinct prefixes), but any future 4th source
   should keep the same `prefix:id` convention rather than assume the column means "Plaid only."
