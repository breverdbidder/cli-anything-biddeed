## Root cause per defect (all confirmed live before any edit)

1. **PA link.** `ff_get_lead` (RPC) resolves `verification.appraiser_url`
   from `public.fl_property_appraiser_configs` (primary) then
   `public.fl_counties.appraiser_url` (fallback) — **not**
   `public.county_appraiser_urls`, which the issue body pointed at but which
   the renderer never actually reads. Both of the RPC's real sources were
   empty for martin (no `fl_property_appraiser_configs` row;
   `fl_counties.appraiser_url` is null for co_no 53) — confirmed via the
   live RPC call before the fix, `verification.appraiser_url: null`.
2. **Buyer name.** `winnerdata.leads.entity_name` and `.contact_name` both
   store the full Section 689.071 deed boilerplate verbatim for this trust
   buyer — confirmed via live `ff_get_lead` response.
3. **CT recording contradiction.** `index.js`'s old `callScript()` derived
   "N days ago" from `auction.auction_date` unconditionally, while the
   Property Profile row read the real `responses.ct_recording_date` (null
   here) and correctly said "Not yet recorded" — two different fields, no
   shared source of truth.
4. **Building value / Coverage A / Construction Quality.**
   `public.fl_parcels` has no standalone building-value column;
   `ff_get_lead` always computes `bldg_val = jv - lnd_val` server-side
   (confirmed via schema query: fl_parcels columns list has `jv`, `lnd_val`,
   no `bldg_val`/`val_building`). For this parcel: jv=1,502,280,
   lnd_val=375,000 → bldg_val=1,127,280, matching the issue's reported
   figure exactly. `const_clas` for this parcel is the string `"0"` (DOR
   unclassified/no-data code), which is JS-truthy, so the old
   `esc(parcel.const_clas) || 'Not established'` rendered `"0"` literally.
5. **Year built not shown.** `parcel.eff_yr_blt`/`act_yr_blt` (1982/1982 for
   this parcel) were only used internally to gate the pre-1990 flag, never
   rendered anywhere on the page.

## Fixes

1. Migration `20260902n_ff_add_martin_pa_config.sql` adds the martin row.
   **Deviation from the issue's suggested URL** (logged per CC_META_PROMPT
   §2.3 — verify the brief's own URL before trusting it): the issue
   specified `https://www.pamartinfl.gov/search/real-property?search={{FOLIO}}&searchField=pin&exact=true`
   — live-curled 2026-09-02, this 404s. The real path (confirmed via the
   site's own nav links) is `/app/search/real-property` (note the `/app`
   prefix). With that correction, a plain GET returns the full record
   server-embedded in a `window.initialState` JSON blob — no JS/Playwright
   needed. Live-verified for this exact parcel:
   `PIN 27-38-40-002-000-00420-9` → `PrimaryOwner: "APOSTOL NICHOLAS"`,
   `SitusAddress: "5755 SW RANCHITO ST PALM CITY FL"`,
   `TotalMarketValue: 1528180` — matches `public.fl_parcels` for this
   parcel. HTTP 200. `county_appraiser_urls` martin row corrected to match
   (data hygiene; not the table the FF worker reads).
2. Renderer already substituted `parcel_url_template` correctly (no code
   change needed for the mechanics) — verified live via `ff_get_lead` RPC
   post-migration: `appraiser_url_is_deep_link: true`,
   `appraiser_url: ".../app/search/real-property?search=27-38-40-002-000-00420-9&searchField=pin&exact=true"`.
   Added: `{{property_appraiser_heading}}` — renders "Property Appraiser —
   verify at source" whenever any URL resolves (deep-link or plain search),
   "Property Appraiser" (unchanged) only when neither
   `fl_property_appraiser_configs` nor `fl_counties` has anything.
   `{{values_source_note}}` — names the source table (`public.fl_parcels`)
   and `dor_source`/`dor_synced_at` when tagged, or says honestly that the
   extraction source isn't tagged for this parcel (true for this case —
   both fields are null).
3. `normalizeBuyerName()` (new, in `ff_format.js`) strips the
   `"with full power and authority..."` clause onward and reformats
   `"<Trust>, <TRUSTEE> as trustee"` → `"<Trust> — <Trustee Title-Cased>,
   trustee"`. Applied to `entity_name`, `contact_name`, the
   AskFetch name split, `call_script`, and `buyer_of_record_rows` (Template
   A's buyer table) — i.e. everywhere a buyer name renders, not just this
   one FF. Non-matching names (no boilerplate clause) pass through
   byte-identical.
4. `callScript()` (moved to `ff_format.js`) now takes an explicit
   `ctRecordingDate` param — the *same* value
   (`responses.ct_recording_date`) the Property Profile row already reads.
   Recorded → `"Certificate of title recorded <date>, case <n>."` Not
   recorded → `"Sale held <auction_date>, certificate of title not yet
   recorded."` — the old unconditional "N days ago" wording is gone.
5. `building_value` / `coverage_a` values now always carry a derivation
   label (`"(derived: market value − land value)"` /
   `"— computed from derived building value; confirm with PA before
   quoting"`) since `fl_parcels` never has a non-derived source at this
   data path — Coverage A's 1.25x formula itself is unchanged (labeling
   only, per non-goals). `construction_type` now renders `"n/a"` for both
   null and the DOR `"0"` (unclassified) code instead of leaking the raw
   `"0"`.
6. `computeFlags()` now embeds the year(s) directly into the pre-1990 flag
   text itself (`"Pre-1990 construction (built 1982) — 4-point inspection
   required"`) so the flag carries its own evidence inline, next to where
   it's asserted, rather than adding a separate profile row.
