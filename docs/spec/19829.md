## Key architectural findings that apply to every phase (see 19829-P1.md for full detail)
- `docs/design/BIDDEED_CLAUDE_UI_PARITY_ARCHITECTURE.md`, cited by the issue as the schema/architecture source,
  does not exist anywhere in this repo. Confirmed by repo-wide search before starting.
- This project's Supabase instance does not expose a `chat` (or `deal`/`artifacts`/`skills`/`connectors`) schema
  to PostgREST — only `{public, graphql_public, pascal, geo_tracker, finance, winnerdata}` are exposed, confirmed
  live with both anon and service_role keys. Every future phase's schema must live in `public` with a
  collision-checked prefix (there is already an unrelated pre-existing `chat_*` table set in `public` — see
  Deviation 2 in 19829-P1.md).
- biddeed.ai has no Clerk/Supabase Auth/login system at all — it is fully anonymous today. P1 shipped a
  stateless HMAC-signed "claimed email" identity as a pragmatic substitute (real tamper-proof separation between
  users, not inbox-ownership verification). P2 (share links) and P3 (alerts/connectors) both assume real
  identity — decide explicitly whether to build on the P1 substitute or invest in real verification first.
- `src/worker.js` deploys via `wrangler deploy --no-bundle` with zero `import` statements — no npm dependency can
  be added without also changing the deploy pipeline (a workflow-file edit, out of scope per standing mandate
  M5). Any future phase needing a library (DOCX parsing, calendar ICS generation, etc.) hits the same wall P1 hit
  for PDF extraction.
