All writes verified scoped to `county='<target>'` only, zero PropertyOnion-sourced values written into clean/verified fields, zero DROP/TRUNCATE/bulk-DELETE.

Working DB access channel discovered/confirmed this session (documented here since it isn't in CLAUDE.md): direct psql to the pooler and `rpc/exec_sql` are both dead in this sandbox (matches prior documented constraint); the Supabase **Management API** `database/query` endpoint (`Authorization: Bearer $SUPABASE_ACCESS_TOKEN`) is live and supports arbitrary SQL incl. writes — this was the channel used for every fix and every verification query this session.
