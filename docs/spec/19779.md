## Mandates applied
- M1: no producer send anywhere in this session — every write stays `status='pending_approval'`.
- M3: title/caption/on-screen text never names a vendor/tool/issue number/run id (enforced in `validate_bolt32_title()`'s banned-phrase list, spot-checked below).
- M7: title generator's protagonist is always the property/a bidder/the bank/the county, never a person; `banned_names_for_case()` additionally cross-checks against `public.multi_county_auctions.owner_name`/`plaintiff` for the target case.

## What this session built

### 1. Migration `20260903e_biddeed_reels_bolt32_template.sql` (applied live via Management API)
- `winnerdata.biddeed_reels` gains: `template`, `title_candidates` (jsonb), `title_chosen`, `beat_map` (jsonb), `loop_frame_ms`, plus two columns beyond the issue's literal list — `video_bolt32_url`, `duration_bolt32_sec` — logged as a deviation (see below). Additive only; no existing column touched.
- `public.log_reel_watch_event(p_code, p_event, p_session_id)` — SECURITY DEFINER RPC, allow-lists `p_event` to `play|25|50|75|100|loop`, resolves `p_code` against `short_code`, writes to `winnerdata.funnel_events` (pre-existing table, 0 rows since creation — confirmed live before this session's first write — so this is genuinely its first writer, not a repurposing of live data).
- `winnerdata.v_reel_retention` — per-reel `plays`/`p50_watch_pct`/`loop_count`/`loop_rate_pct`, `security_invoker=true`, no anon/authenticated grant (read via Management API, same access pattern every other winnerdata read in this pipeline uses).
- **Deviation, fixed live this session**: the RPC's first version used `gen_random_bytes(12)` for an auto-generated session id, which raised `function gen_random_bytes(integer) does not exist` at call time despite `pgcrypto` being installed (extension present, but the function did not resolve inside this `SECURITY DEFINER`'s `search_path`). Replaced with `gen_random_uuid()::text`, which is core to Postgres 13+ and requires no extension resolution. Re-verified live (see Evidence below) after the fix.

### 2. `scripts/biddeed_reels_lib.py` — bolt32 module (title generator, validator, beat sheet, assembly)
- `generate_bolt32_titles()` / `validate_bolt32_title()` / `pick_bolt32_title()` — 5 candidates per property, grapheme-aware two-emoji check (`_peel_bolt32_emoji_suffix()`, matches the 2-codepoint heart+VS16 token whole), M7 banned-name + vendor-phrase check, stakes-score check (`$`/digit/superlative).
- `BOLT32_SEGMENTS` / `assemble_video_bolt32()` — 7 visual segments implementing the spec's 6 named beats (durations sum to exactly 32.0s pre-encode); the `tension` beat is split into 2 sub-cuts (aerial_tight, then street), not the spec's literal "3-4 visual cuts" — **deviation, logged**: this pipeline has exactly 3 stills per row and no comp-card generator, so 2 cuts is what real imagery supports.
- `assert_bolt32_duration()` / `assert_bolt32_tts_model()` — the two hard DoD gates, each independently unit-testable (negative tests (c)/(d) below run these directly, no ffmpeg call needed).
- `build_bolt32_script_and_caption()` / `build_bolt32_beat_map()` — eleven_v3-tagged script (`[surprised]` hook / neutral setup / `[serious]` tension / `[excited]` payoff / `[warm]` loop line), beat_map jsonb.
- **Deviation, found and fixed live this session**: the first `assemble_video_bolt32()` call against real data failed with ffmpeg's `Filter not found` because the loop-line overlay text ("And that's why nobody else bid.") contained an apostrophe — `_escape_drawtext()`'s backslash-escaping of `'` is not valid inside ffmpeg's own single-quoted filtergraph option value (a real, previously-latent bug in the shared escaping helper that no prior v1/v2/presale overlay text had ever triggered, since none of them contained an apostrophe). Fixed by rewording bolt32's on-screen payoff/loop-line text to avoid contractions (`"That is why nobody else bid."` etc.) rather than patching the shared helper used by three other templates (K3 surgical scope) — the spoken TTS text is unaffected (contractions there are fine; only the drawtext-rendered strings needed the change).

### 3. `scripts/biddeed_reels_pipeline_bolt32.py` — new pipeline
- Re-renders EXISTING rows by `id`, never re-fetches Maps imagery or re-runs vision scoring (reuses `aerial_wide_url`/`aerial_tight_url`/`street_url`/`condition_json` from the row's existing v2/presale render).
- `banned_names_for_case()` — queries `public.multi_county_auctions` by county, matches `case_number` client-side after normalizing punctuation/case, extracts `owner_name`/`plaintiff` tokens (stopword-filtered).
  - **Real bug found and fixed live, mid-session**: the first version matched `case_number ilike *<first token>*`, which for a case number like `"2025 CC 003163"` wildcarded on just `"2025"` — live-reproduced as a false-positive banned-name hit (`'Home'`, `'the'`) pulled from an unrelated row in the same county that merely shared the filing year. Fixed to fetch by county only (bounded `limit=1000`) and match the full normalized case number client-side before extracting any name tokens. Re-ran the one affected row after the fix — see Evidence.
- `_sql_val()` — **real bug found and fixed live, mid-session**: the `hashtags` column has no branch in the first version's `_sql_val()`, so it fell through to `sql_str()` and produced a malformed Postgres array literal (`ERROR 22P02: malformed array literal`) on the very first live write attempt. Fixed by adding the `hashtags -> sql_text_array()` branch (the same helper `biddeed_reels_pipeline_v2.py` already uses for the same column).
- `--self-test` mode runs negative tests (a)-(d) with no network/DB/ffmpeg calls.

## Deviations from spec (all logged inline above, summarized here)
1. `video_bolt32_url`/`duration_bolt32_sec` columns added beyond the issue's literal 5-column list — needed so a bolt32 render can coexist with the row's existing v1/v2/presale video without overwriting it.
2. `tension` beat uses 2 visual sub-cuts, not the spec's literal "3-4" — bounded by the 3 stills this pipeline actually has per row (no comp-card generator exists).
3. On-screen payoff/loop-line overlay text avoids contractions (apostrophes) — a real ffmpeg filtergraph escaping bug in the shared `_escape_drawtext()` helper, worked around at the call site rather than patched shared code (K3).
4. "R2 links" are Supabase Storage public URLs — same established deviation as v1/v2/presale (`docs/spec/19736.md`).
5. `/reels` gallery/single-reel player still plays `video_v2_url`, not `video_bolt32_url` — the ask was the measurement mechanism, not swapping the default player asset.
6. `gen_random_bytes` → `gen_random_uuid()::text` in the watch-event RPC — a real, live-reproduced Postgres/pgcrypto resolution failure inside a `SECURITY DEFINER` function, fixed same session.
7. `banned_names_for_case()`'s case-number match narrowed from a first-token wildcard (false-positive-prone) to full normalized-string equality — a real bug, fixed same session, one row re-run after the fix.
