| Platform | Vault secret names written by this Worker | Read via |
|---|---|---|
| Meta (Facebook Page) | `meta_page_access_token`, `meta_page_id`, `meta_user_token_expires_at` | `get_vault_secret_mcp('meta_page_access_token')` etc. |
| Meta (Instagram Business) | `ig_business_account_id` (shares `meta_page_access_token` as its access token) | same |
| TikTok | `tiktok_access_token`, `tiktok_refresh_token`, `tiktok_open_id`, `tiktok_token_expires_at` | same |
| X | `x_access_token`, `x_refresh_token` | same |

**Naming mismatch flagged, not fixed (out of scope — publishing lanes are explicitly excluded
from this issue):** `agents/distribution/facebook.py`/`instagram.py` already exist (from the
CP3g distribution-lane build) and declare `required_secrets = ["facebook_page_access_token",
"facebook_page_id"]` / `["instagram_access_token", "instagram_business_account_id"]` —
different vault names than what this issue's own body asks this page to write
(`meta_page_access_token`/`meta_page_id`/`ig_business_account_id`). Whoever builds the Meta
publishing lane needs to either (a) update those two adapters' `required_secrets` to the names
above, or (b) have this page additionally mirror the same value under both naming schemes. I
did not silently pick one — the issue body names the four secrets above explicitly, so that's
what got written; reconciling adapter naming is a **residual item for the publishing-lane
issue**, not this one.
