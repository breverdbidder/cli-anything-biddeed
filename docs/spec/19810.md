## What was built

### Schema (this repo — `supabase/migrations/20260903j_cfo_invoice_audit_19810.sql`)
- `finance.vendor_invoices` / `finance.vendor_invoice_lines` — exactly the columns the issue
  specifies, plus `extraction_method` and `dispute_reply`/`dispute_reply_at` for future use.
  RLS enabled, `cfo_agent_ro_select` SELECT-only policy, no anon/authenticated grant (verified
  live post-DDL — see SQL VERIFICATION).
- 6 `public.cfo_invoice_*` SECURITY DEFINER RPCs (owner `postgres`, EXECUTE granted to
  `cfo_agent_ro` only) — this Worker holds no `service_role` key (see
  `worker/docs/PORTING_NOTES.md`), so every write to `finance.*` has to go through a gated
  wrapper, same as every prior bank-engine/CFO migration:
  - `cfo_invoice_ingest` — upsert-on-(vendor, invoice_number), replaces lines idempotently,
    best-effort bank-transaction link (`abs(amount_cents - total_cents) <= 1`, `posted_on`
    within issued_on ± 5 days — magnitude only, not signed direction, see the migration's
    comment on why: 3 sign conventions coexist across Plaid/file-import/SimpleFIN sources in
    this table already).
  - `cfo_invoice_write_verification`, `cfo_invoice_set_status`, `cfo_invoice_save_dispute`.
  - `cfo_invoice_get_vendor_credential(name)` — gated vault accessor, hard allow-list of one
    name (`vercel_api_token_brevardbidderai`), per CLAUDE.md's CREDENTIAL HANDLING section
    (never a bare `vault_secret`-style passthrough).
  - `cfo_invoice_check_anomalies(invoice_id)` — the 4 anomaly rules, pure SQL, writes
    `finance.recon_exceptions` rows (`reason` prefixed `invoice_anomaly:`), idempotent (checks
    `reason` for an exact-text duplicate before inserting).

### Worker (`breverdbidder/everest-cfo-agent`, commits `fa9347d`, `98ba38a`)
- `worker/src/lib/vendorInvoices.ts` — data layer (direct RLS reads, RPC writes).
- `worker/src/lib/invoiceExtract.ts` — DeepSeek extraction (primary, per spec) +
  **deterministic regex fallback** (used this session because `DEEPSEEK_API_KEY` is not
  provisioned on this Worker — see below). 7 unit tests against the exact trigger-case invoice
  text. `extraction_method` is always recorded on the stored invoice so a fallback-parsed
  record is never silently indistinguishable from an LLM-parsed one.
- `worker/src/lib/vendorAdapters.ts` — adapter registry. Real Vercel `/v6/deployments` adapter
  (sums build duration across deployments in the invoice period, compares to the billed Build
  CPU Minutes line). Stub adapters registered for supabase/cloudflare/anthropic/openai/deepseek
  that return an explicit `UNVERIFIABLE — credential missing: <name>` rather than a fabricated
  number — additive, per the issue's "adapter registry" requirement.
- `worker/src/lib/invoiceDispute.ts` — DeepSeek-drafted dispute letter (primary) +
  deterministic fallback template (used this session, same reason). Frames the Vercel case as a
  **goodwill-credit request**, not a "your meter is wrong" claim, per the issue's explicit
  instruction (a fix was applied mid-session for a redundant sentence in the fallback template —
  see Deviations).
- `worker/src/index.ts` / `agent.ts` — new routes: `GET /api/invoices`, `GET /api/invoices/:id`,
  `POST /api/invoices/ingest` (PDF via `unpdf`, or pasted text, or multipart file), `POST
  /api/invoices/:id/verify`, `POST /api/invoices/:id/dispute`. All behind this Worker's existing
  `X-CFO-Secret` gate (see Deviations — this Worker's whole SPA is gated client-side, unlike
  bank-engine's public `/import` page, so `GET /api/invoices` follows this Worker's own
  convention rather than bank-engine's).
- `worker/webapp/components/InvoicesPanel.tsx` + a `Dashboard`/`Invoices` tab switcher in
  `App.tsx` — ingest form (paste text or upload PDF), invoice list with status badges, per-line
  billed-vs-verified detail with variance %, anomaly flags, "Run verification" and "Draft
  dispute" actions, draft display (marked "not sent — propose-only").

### Non-goals honored

## Deviations from spec

1. **`GET /api/invoices` is gated (`X-CFO-Secret` required), not a public page** like
   bank-engine's `GET /import`. This Worker's entire SPA already requires the shared secret
   client-side (entered once via the `Gate` component into `sessionStorage`, sent as a header on
   every `/api/*` call) — a different security model than bank-engine's multi-page app. The
   "simple upload form... from a browser" requirement is satisfied by the new Invoices tab's
   ingest form instead of a second, differently-gated page.
2. **DeepSeek extraction/dispute-drafting ran via deterministic fallback this session**, not the
   live LLM path, because `DEEPSEEK_API_KEY` is not provisioned (see "What's blocked"). Both
   paths are fully coded; only the credential is missing. `extraction_method`/`method` fields
   make this observable per-record, never silently mislabeled.
3. **`entity_code=biddeed` on the ingested invoice is INFERRED**, not stated in the invoice
   itself — reasoned from the issue's own reference to biddeed-web being Vercel-hosted (soon
   migrating off, per #19678). Flagging rather than asserting VERIFIED.
4. **Anomaly rule 4 (recurring run-rate) did not fire** — `finance.v_recurring_costs` has no
   matched "Vercel" vendor pattern from bank-transaction categorization yet (not investigated
   further; out of this issue's scope to backfill category_rules).
5. **Vercel adapter's exact field names (`buildingAt`/`ready`) are UNTESTED against a real
   Vercel API response** — no working credential exists to test with this session. Written from
   documented API shape, flagged rather than claimed VERIFIED.
