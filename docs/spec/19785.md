### 2. PID-safety guardrail (issue comment, applying `docs/intent/19678.md`)
19678's literal rule targets a Node/`next-server` broad-kill failure mode; the issue comment asks
for the same discipline applied to Chromium. `reel_site_reveal.py` never shells out to
`pkill`/`killall` anywhere — every capture uses `with sync_playwright() as p:` plus nested
try/finally `browser.close()`/`context.close()`/`page.close()`, so Playwright's own driver owns
the full subprocess lifecycle end to end. One `BrowserContext`/page open at a time per capture,
closed before the next capture starts, per the comment's memory-budget instruction.
