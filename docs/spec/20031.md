### Worker (src/worker.js)
- New `capturePosthogServer(distinctId, event, properties)` helper — server-side
  PostHog capture using the same public project key already embedded client-side in
  `POSTHOG_SCRIPT` (no new secret/vault entry needed).
- `reel_click` (`/r/:code`), `deal_view`+`gate_view` (`/deal/:county/:slug`),
  `email_capture` (`/deal/.../lead`), `signup` (`/chat/api/identity`),
  `checkout_started` (`/subscribe/checkout`) all now dual-emit:
  `winnerdata.funnel_events` row (via `log_funnel_event`) + PostHog capture, both
  carrying `reel_code`/`variant_id`/`county`/`sale_type` when known.
- `/subscribe/checkout` resolves `first_reel_code`/`first_county` server-side from
  `public.lead_profiles` by the `bd_vid` visitor id the client now sends (read via
  the pre-existing `anon_select_leads` RLS policy — no new grant). Additive only:
  missing/unknown visitor_id never blocks checkout (negative test, verified below).
- Client-side: `/subscribe` page now reads `localStorage.bd_vid` and sends it as
  `visitor_id`; `subscribe_redirect` PostHog event renamed to `checkout_started` to
  match the issue's exact event-name contract; `ensureChatIdentity()` now also sends
  `bd_vid` to `/chat/api/identity`.

## Deviations from intent
- Deliverable #6 (per-variant scoreboard exposure) required no new SQL: confirmed
  `winnerdata.v_variant_scoreboard` already had `plays/clicks/captures/ctr` before writing
  anything (from issue #19782's original migration). Documented rather than rebuilt, per K2.
- "biddeed-web" is named in the issue body as the surface for `signup`/`checkout_started`,
  but no such repo exists in this checkout or in CLAUDE.md's active repo list — `src/worker.js`
  is the only code in this repo that actually serves `/subscribe`, `/chat/api/identity`, and
  `/deal/*`, so it was treated as the site's real "biddeed-web" surface. Flagged rather than
  blocked on an inaccessible repo (zero-HITL: picked the defensible alternative).
- `never_list_hits` in `v_gspi_daily` is a best-effort proxy (`reel_variant_review.decision =
  'rejected' AND note ILIKE '%never%list%'`) — no dedicated never-list-hit table exists
  anywhere in the schema (confirmed via `information_schema.tables` search). Reads 0 honestly
  today rather than fabricating a number.
- `signup` counts chat-identity **token issuances**, not verified first-ever signups: the
  client only calls `/chat/api/identity` when it has no cached unexpired `bd_chat_token`
  (30-day TTL), so a returning user past that TTL re-triggers it. No new table was added to
  track true first-touch signup without violating the intent's "no new tables" guardrail;
  this is the closest honest measurement available today.
- CAC/LTV in `finance.v_gtm_unit_economics` are built on `finance.expense_ledger`, which has
  only 2 rows live today (ElevenLabs, GitHub) — real number, thin source. Documented as
  INFERRED in the memo/`/spi` output, never presented as a full vendor-spend feed.
