## What this session built

### 1. Migration `supabase/migrations/20260903f_youtube_publish_lane.sql` (applied live via Management API)
- `public.youtube_quota_ledger(day_pacific pk, units_used, calls jsonb, updated_at)` — RLS enabled, no anon/authenticated policy.
- `public.youtube_quota_preflight_reserve(p_units, p_call_name, p_daily_cap=10000, p_reserve=400)` — SECURITY DEFINER, `SELECT ... FOR UPDATE` inside the same transaction as the reservation `UPDATE`, so it's atomic under concurrent callers, not just "probably fine at 6 calls/day." `EXECUTE` restricted to `service_role`. This one function **is** the pre-flight check the issue asks for (deliverable 2) — the issue's own math (10,000 cap − 400 reserve = 9,600 budget ÷ 1,600/upload = exactly 6) means the unit-based refusal IS the "6/day maximum," not a second independent counter that could drift from it.
- `public.youtube_token_health(id, checked_at, ok, error)` — RLS enabled, no anon/authenticated policy.
- `public.youtube_uploads` — new table (deliberately NOT a `reel_variants` column add — K3 surgical scope, #19782 owns that table's schema and this issue doesn't name it for alteration). Stores the built title/description/tags/pinned-comment/UTM-link per variant plus upload tracking. `privacy_status text not null default 'private' check (privacy_status = 'private')` — DB-level enforcement of M8, independent of the application code. RLS enabled, no anon/authenticated policy.
- `winnerdata.youtube_publish_queue` (view) — top-6 selection (deliverable 5). Lives in `winnerdata`, not `public`, because it selects from `winnerdata.v_variant_scoreboard`/`reel_variants`/`biddeed_reels`, and this project's `service_role` gets `permission denied for schema winnerdata` (42501) over PostgREST — **live-confirmed this session**, matching `scripts/biddeed_reels_lib.py`'s own module docstring ("winnerdata.\* is NOT exposed via PostgREST on this project"). Read exclusively via the Supabase Management API (`SUPABASE_ACCESS_TOKEN`), same as every other winnerdata access in this repo — not a new access pattern.
- **Deviation, fixed live this session**: the first version of the view put `hashtags`/`county` before a later-added `video_url` column, and Postgres's `CREATE OR REPLACE VIEW` refused the column reorder (`42P16: cannot change name of view column`). Fixed with `DROP VIEW IF EXISTS` + `CREATE VIEW` instead of `CREATE OR REPLACE VIEW`.
- **Real bug found and fixed before any live insert**: the first `youtube_publish_queue` definition omitted `rv.video_url` entirely — `uploader.py` needs the actual video file URL (not `short_url`, which is the deal-page redirect, not video bytes) to perform a resumable upload. Added `rv.video_url` to the view and removed the incorrect `row.get("video_url") or row.get("short_url")` fallback from `uploader.py` (that fallback would have tried to upload a redirect-page HTML response as if it were an MP4).

### 4. `agents/youtube/uploader.py` — deliverable 1

Reserves quota before ever attempting an upload; never refunds a reservation on failure (conservative budgeting, matches the issue's own framing of the constraint). `--self-test` runs negative tests (a)/(b)/(c)/(d) with zero network/DB calls.

## Deviations from spec (all logged inline above, summarized here)
1. `youtube_publish_queue` lives in `winnerdata`, not `public` — required by the same PostgREST schema restriction every other winnerdata object in this repo already works around (live-confirmed, not assumed).
2. `youtube_uploads` is a new table, not new columns on `reel_variants` — K3 surgical scope, #19782 owns that table.
3. Analytics calls are budgeted against the shared 10,000-unit pool per the issue's explicit instruction, even though YouTube Analytics generally has its own separate Google-side quota bucket — followed the issue's stated hard constraint rather than second-guessing it (costs nothing to over-budget).
4. `selfDeclaredMadeForKids: false` is a hard-coded default in the upload request body — the issue doesn't specify this required YouTube API field; INFERRED reasonable default (no content in this pipeline is kids-directed), flagged here rather than silently assumed.
5. Category stays `22` (People & Blogs) for every upload — no clearer fit was identifiable from the property/auction content type available, per the issue's own "unless a better fit is justified" carve-out.
6. `youtube_publish_queue`'s ranking (ctr → watch-through → plays, all `NULLS LAST`, tiebreak on `created_at`) is an INFERRED formula — `v_variant_scoreboard` (#19782) ships the individual engagement fields but no single composite "rank" column, and the issue names "the Analyst's variant ranking" without giving its exact formula.
7. Two new GHA workflow files were created despite M5's blanket "no workflow-file edits" line — read consistently with M2's identical "unless the issue body names it" carve-out, since deliverable 7 explicitly names both files. Logged for auditability, not treated as a real conflict.
