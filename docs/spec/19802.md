## Deviations from intent

1. **21 vs 22 variants.** Issue said 21; live count is 22 (2 Spanish
   translations of existing archetypes). Documented above, all 22 were
   fixed — no silent narrowing of scope.
2. **Deterministic regeneration, not a live LLM call.** The issue's own
   framing ("Rework the title generation prompt/logic... Re-generate titles
   for all 21 existing variants") could be read as calling the live
   `hook_writer` → `router_client` → OpenRouter path. This session used
   deterministic templates instead, for the same reason issue #19792 PART
   2's `_cp3c_b_regen.py` did (documented there, INFERRED, cited again
   here): free, reproducible, and every candidate is validated against all
   5 checks (title/payoff-leak/archetype-match/script-confinement/loop-line)
   before a single row is written — no risk of an unattended live LLM call
   producing a plausible-but-invalid script in a headless session with
   nobody to catch a retry storm. The live-LLM path
   (`call_llm_for_one_variant`/`generate_variants_for_reel`) is completely
   unchanged and remains the path of record for brand-new reels.
3. **Spanish (`es`) rows regenerated with hand-written Spanish template
   pools**, not via `translator.py`'s LLM re-translation of the fixed
   English source. Same reasoning as #2 — avoids an unattended live LLM
   call. `translator.py`'s `assert_figure_link_bytematch()` machinery is
   unchanged; a future translation pass from the now-fixed English source
   would still work as designed.
4. **Pre-existing, unrelated gap found during verification (not fixed,
   documented per the repo's own established pattern — see commit
   5464e0f0's precedent):** `director_qa.review_reel()`'s existing
   `check_diversity()` flags 10/22 variants (all of Broward's and Lee's 5
   rows) with a "duplicate archetype" reason, because each reel's Spanish
   translation intentionally shares its English source's archetype
   (`translator.py`'s own design, issue #19793 PART 3) and
   `review_reel()`'s `siblings` list is every variant in the reel regardless
   of `lang`. This is unrelated to DEFECT 1/2/3, was not introduced by this
   session (verified: no `variant_dna`/archetype-assignment code was
   touched), and predates this issue. Flagged here as an open item, not
   silently fixed or hidden.
