## CP-C1 — Query universe

**VERIFIED**, re-checked live at 2026-09-04T00:19:02Z (retried once after a transient 503 — errored, not failed, per protocol): `content-range: 0-0/365` → **365 rows** in `public.seo_query_universe`.

- **Table decision:** `content_library`'s required shape (`auction_date`, `content_id`, `platform`, `type`, `content` jsonb) is a social-post queue — checked live via the OpenAPI schema, it has no query/cluster/intent/difficulty columns and its required fields don't fit a keyword row. New table `public.seo_query_universe` instead (migration `supabase/migrations/20260903l_cmo_factory_cpc1_seo_query_universe.sql`, RLS on, `service_role`-only policy, no anon grant per M2).
- **Composition:** 67 counties × 5 issue-specified templates (foreclosure auction / tax deed sale / auction calendar / how to bid / surplus funds) = 335 rows, `source='generated_template'`. Plus 30 authored informational/state-wide queries, `source='authored_informational'`.
- **Deviation, disclosed:** the issue asked for real questions "mined from `claude_chat_history` and the `/chat` transcripts in this repo's Worker logs." Checked both live: `claude_chat_history` holds Claude Code dev-session transcripts about repo setup (sample row: "Create a new .env file..."), not end-user property questions. `src/worker.js`'s `/chat/api` is a stateless SSE relay to `claude-router` and persists no message content anywhere — there is no transcript store to mine. Per CC_META_PROMPT.md §2.3 ("the DoD query itself may be wrong"), this is logged rather than silently substituted: the 30 informational queries are **authored** from the same FL foreclosure/tax-deed domain knowledge already canonical to this repo, tagged `source='authored_informational'`, not claimed as mined.
- **Clustering:** `intent` ∈ {informational, navigational, transactional} (204 navigational / 158 informational / 3 transactional). `difficulty_estimate` is a heuristic (query specificity + incumbent-competition tier for the 10 largest counties) — **no live keyword-difficulty API was reachable this session**; `difficulty_method` on every row states this plainly rather than implying a real SERP-tool pull.

20 sample rows and the full breakdown are in the PR-time session output; re-derivable any time via:
```sql
select query_text, county_slug, query_type, intent, difficulty_estimate, target_page
from public.seo_query_universe order by created_at limit 20;
```

### Legal content — fact-checked, not recalled
Every statutory claim was verified against the live text at leg.state.fl.us this session (not written from training-data memory):
- Fla. Stat. §197.552: tax deed "no right, interest, restriction, or other covenant shall survive... except [certain governmental liens]" — mortgages are not an exception → **tax deed sales wipe mortgages** (matches issue's Hard rule).
- Fla. Stat. §45.031(3): 5% deposit at time of judicial sale.
- Fla. Stat. §45.0315: mortgagor may redeem "at any time before the later of the filing of a certificate of sale... or the time specified in the judgment."
- Fla. Stat. §197.472: tax certificate "may [be] redeem[ed]... at any time after the certificate is issued and before a tax deed is issued."
- Fla. Stat. §197.542(2): tax deed deposit "5 percent of the bid or $200, whichever is greater"; full payment due within 24 hours (excl. weekends/holidays).
- Ad valorem tax-lien priority (Fla. Stat. §197.122) is why **foreclosure sales do not wipe tax liens** — matches issue's Hard rule.

1. **`multi_county_auctions` rows carry propertyonion-sourced fields.** Live query confirmed `data_source: "propertyonion"`, `source_url: "https://propertyonion.com/..."`, `photo_url` pointing at `s3.amazonaws.com/propertyonion/...`, plus a full `po_*` column family (`po_market_value`, `po_avm_value`, `po_sold_amount`, etc.) on rows in the table this and every other biddeed.ai auction surface reads from. Hard rule #1 ("never name the competitor," "no scraped competitor content") is honored on the new pages by construction (`scripts/audit-site.mjs`'s `COMPETITOR_FIELD_LEAK` check refuses to let any `/counties` file reference these columns), but the underlying data risk is repo-wide, not specific to this issue — any other surface that does a `select *` on this table and renders `photo_url`/`source_url` verbatim would leak it. Worth a dedicated audit across `app/api/auctions/*` and the legacy Worker's `/county/:slug` and `/chat` handlers.
2. **`/radar` and 4 other live pages have zero meta description / zero H1** (CP-C0 table above) — pre-existing, unrelated to this issue's scope, flagged for a future SEO pass.
3. **`CMO_FACTORY_META_PROMPT.md` and `CONTENT_SEO_AEO_GEO_META_PROMPT.md`**, both cited by name in the issue body as required reading, do not exist in this repo (checked: `find . -iname "*META_PROMPT*"` returns only `CC_META_PROMPT.md` and `MAS_SOP_META_PROMPT.md`).
