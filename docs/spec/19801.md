## Problem (VERIFIED live, 2026-09-03)

Run 33763910190 (issue #19794) failed at the post-job "Commit changes" / `actions/checkout` cleanup
step with `fatal: No url found for submodule path 'zonewise-video' in .gitmodules`, exit 128.

Root cause, confirmed by inspection of `git ls-files -s` on `main` at commit `9e2d9251` (pre-fix HEAD):

```
100644 76ba86e...  .github/workflows/render-zonewise-video.yml
160000 39ebd1d7...  zonewise-video          <- gitlink, mode 160000
```

`.gitmodules` on `main` was effectively empty (`xxd .gitmodules` → single `0a` byte, i.e. one blank
line) — so the index carried a gitlink entry with nothing in `.gitmodules` to resolve it. `git
submodule foreach` (which `actions/checkout`'s post-job cleanup runs) fails hard on any such
mismatch, on **every** checkout of this repo, not just #19794's run.

## Diagnosis: (a) real submodule vs (b) stray gitlink

Investigated per the issue's explicit instruction not to guess:

- `breverdbidder/zonewise-video` **does exist** as a real, non-empty repo (`gh repo view` confirmed),
  and the pinned commit `39ebd1d70d64ea7341cceb6bcc85463e1cccd53c` **does exist** in that repo
  (`gh api repos/.../commits/39ebd1d7...` returned the sha) — so this wasn't a reference to a
  nonexistent/deleted repo either.
- `git log --diff-filter=A -- zonewise-video` traced the gitlink's addition to commit `9397e48c`,
  authored by the bot identity `Claude-Code <claude@biddeed.ai>`, commit message just
  `"summit: GHA dispatch session"`, diff stat `zonewise-video | 1 +` — i.e. a single gitlink entry
  added with **no accompanying `.gitmodules` change and no real files**. Classic signature of an
  accidental `git add` on a directory that itself contained a nested `.git` (from a prior session
  cloning `zonewise-video` into the repo root), not a deliberate `git submodule add`.
  `zonewise-video/` in the working tree was empty pre-fix (`ls -la` → only `.` and `..`).
  `git log --all --follow -p -- .gitmodules` shows the file's only real content-adjacent commit
  (`200343bb`, "Create .gitmodules") copied it from an unrelated test `__init__.py` file — i.e.
  `.gitmodules` was created essentially blank and never wired to any real submodule, including this one.
- Grepped every workflow/doc that actually consumes `zonewise-video` content:
  `render-zonewise-video.yml`, `video-render.yml`, `production-assets.yml` — **all three** use a
  separate `actions/checkout@v4` step with `repository: breverdbidder/zonewise-video` and
  `path: zonewise-video-src`, i.e. an independent sibling checkout, never git-submodule mechanics
  against the `zonewise-video` path in *this* repo's tree.

Conclusion: **option (b)** — the gitlink was stray/accidental, never a real submodule, and nothing
in the repo depends on it existing. No `.gitmodules` entry was needed.

## Fix

```
git rm --cached zonewise-video
```

Committed as `c70ea908` on `main`, pushed to `origin/main`.
