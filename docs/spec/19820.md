## Step 2 — flip biddeed-web main → Cloudflare (breverdbidder/biddeed-web)
Three commits, pushed directly to `main` (not a PR — matches this repo's established
direct-to-main convention and the issue's own step ordering, which gates only the
*homepage* PR, not this infra change):

1. `ea2be91` — added a `push: branches: [main]` trigger to `cloudflare-production.yml`
   (previously `workflow_dispatch`-only) and gated the Vercel job in `ci-deploy.yml`
   behind `github.event_name == 'workflow_dispatch' || vars.DEPLOY_TO_VERCEL == 'true'`
   (repo variable, unset ⇒ false by default). Not deleted, per the issue's explicit
   instruction — still runnable manually as a rollback path.
2. `270ba3a` — the first auto-triggered run
   ([33818259706](https://github.com/breverdbidder/biddeed-web/actions/runs/33818259706))
   failed immediately: `npm run cf:build:production` has never been a real script
   (`package.json` only ever defined `cf:build`), and `wrangler.production.jsonc` did
   not exist on `main` at all. The currently-live Worker (`be91c339`) was evidently
   deployed from a repo state that predates `d6a56aa8` (the homepage-PR merge), which is
   what diverged `main` away from having these. Recreated `wrangler.production.jsonc`
   as the production mirror of `wrangler.staging.jsonc` and fixed the script reference.
3. `ff1644d` — second auto-triggered run
   ([33818418481](https://github.com/breverdbidder/biddeed-web/actions/runs/33818418481))
   still failed: `opennextjs-cloudflare build` refuses to run non-interactively when no
   bare `wrangler.jsonc` exists at the repo root and no `--config` was passed — which
   was true for `cf:build` all along (verified against
   `node_modules/@opennextjs/cloudflare` source: the check is a literal filename match,
   only skipped when `--config` is passed explicitly). This means `cloudflare-staging.yml`
   had the identical latent bug (never actually exercised — no evidence it had run since
   this shape was introduced in `7b548d6`). Fixed both workflows to pass
   `--config wrangler.<env>.jsonc` to the build command directly.

Third run ([33818541225](https://github.com/breverdbidder/biddeed-web/actions/runs/33818541225))
succeeded end-to-end: build → deploy → smoke checks, ~4 min. This is the strongest form
of the requested proof — an actual push triggered an actual build-from-source deploy
that landed on biddeed.ai, not just a static header check.
