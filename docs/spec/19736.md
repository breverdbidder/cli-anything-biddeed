## Deviations from directive #3's literal text
1. **T10 router change implemented in addition to the pipeline-side OpenRouter cascade**, per the
   issue comment's own explicit "T10 (router)" section — not an unrequested addition. The
   claude-router edge function's vision cascade now uses OpenRouter for its own T1/T1.5, so
   fallback 2 (calling the router) and the pipeline's own primary/fallback-1 hit the same
   underlying provider — by design, this means fallback 2 only actually diverges once it reaches
   the router's T2 (Claude Haiku OAuth), which is the intended final floor.
2. **DeepSeek-vision availability check implemented as a live `/api/v1/models` fetch**, both in
   the pipeline (`_openrouter_model_available()`, in-process cached) and in claude-router
   (`openRouterModelAvailable()`, no cache — Deno edge function instances are not guaranteed
   warm/shared across invocations, and Ariel's own directive explicitly called out that a slug's
   past existence should never be assumed after the `:free` GLM slug vanished).
3. **Two of the 2nd-and-later retry passes were re-invocations of the same script with no code
   change**, not new fixes — the remaining failures after pass 1 were transient Supabase
   Storage/PostgREST edge errors (`544`, `520`, `521`), independently confirmed transient via an
   out-of-band diagnostic (isolated `match_parcel()` calls succeeded immediately against the same
   addresses that had just failed inside the pipeline). Retrying a documented, previously-seen
   transient infra error is consistent with this pipeline's own existing retry/backoff commentary
   in `pg_rest()`, not a new judgment call.
4. **`supabase` CLI was not pre-installed** in this session's sandbox — used `npx --yes supabase`
   (pulls the CLI + downloads the `edge-runtime` bundler image on first use) to deploy
   `claude-router`. This is the standard supported invocation for the CLI, not a workaround.
