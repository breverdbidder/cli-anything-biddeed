## Blocker (structural, not a workaround failure)
`gh workflow run cloudflare-exit-gate.yml -R breverdbidder/zonewise-web --ref cf-exit` → `HTTP 422: Workflow does not have 'workflow_dispatch' trigger`. Root cause confirmed via `gh api repos/breverdbidder/zonewise-web/contents/.github/workflows?ref=main` — neither new workflow file exists on `main` yet. GitHub's `workflow_dispatch` API only resolves workflow definitions from the **default branch**, regardless of which ref is targeted for the run. Since the intent file (guardrail #1) explicitly forbids pushing to `main`, this cannot be worked around pre-merge. No live Cloudflare/Vercel API call has been made; no workers.dev URL exists. This is the genuine data ceiling for this session — not a credential/authorization question, so per the session's own instructions it's reported here rather than worked around.

This is a deliberate boundary, not a capability gap.
