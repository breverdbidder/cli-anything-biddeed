## Live defects found this session (reported, not fixed — out of explicit scope)

1. **`/county/:slug` was 500ing in production** before this session's fix (see item 2 above). This existed in production for roughly 2.5 hours (commit `cc021646` at `08:55:29Z`, fixed by this session's push). Every inbound link/backlink to `/county/*` was broken during that window.
2. **Miami-Dade county-slug mismatch, reconfirmed live**: `lib/counties.ts` (biddeed-web) gives Miami-Dade the slug `miami-dade`; `getCountyAuctionData()` passes that straight to `auctions_calendar_counts(p_county=...)`, which returns `total=0` for `'miami-dade'` (hyphen) and `total=40` for `'miami_dade'` (underscore) — same window, same call, only the county string changed. This is the same defect the #19830 K2 verification already flagged on PR #17 (`2026-09-04T03:21:09Z` comment); it was not fixed between then and this session. Reported again with a fresh paired reproduction in this session's PR #17 comment. **Recommended fix** (not applied): normalize `p_county` inside `auctions_calendar_counts()` (replace `-` with `_` before matching), or have `getCountyAuctionData()` pass the underscore form while keeping the URL slug hyphenated.
3. **`COUNTY_DISPLAY` in `src/worker.js` is missing Collier County** — 66 of 67 FL counties present. `esbuild` warns of two *duplicate* keys (`brevard`, `lafayette`) at build time, but duplicates alone don't explain a missing county (a duplicate just means the later value wins, key count is still correct) — direct `Object.keys().length` count confirms 66, and a diff against the full 67-county list identifies `collier` as the specific one absent. Effect: `/counties/collier` is unreachable from the sitemap and the local `/counties` index (`buildCountiesIndex()`) even though it's a real Florida county with real auction data. Not fixed here — pre-existing, unrelated to the `/county` → `/counties` migration this issue is scoped to.
