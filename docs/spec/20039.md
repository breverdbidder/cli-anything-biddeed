## Deviations from intent
1. **sync-credentials-to-vault.yml was retimed, not disabled**, even though the issue body's scope item 4 lists it alongside cmo-factory-distribution-scheduler.yml as one of "the two chronically failing scheduled workflows." Log tail inspection (runs 33972192214, 33969263156) showed the actual failures are transient Cloudflare 520 / PostgREST "schema cache" 503 errors during DB restarts — self-healing on the very next 15-min tick (adjacent runs at 14:21 and 14:47 both succeeded). This is not a logic bug and not the `gtm_factory_halt`-style by-design gate the issue anticipated; disabling it would stop the Smart Router's credential rotation into `vault.secrets`, a live dependency. Zero-business-logic constraint also forbids adding retry logic. Retimed off the quarter-hour instead, which is the correct action under scope item 3 and addresses the actual root cause (restart-correlated origin errors) better than disabling would.
2. **Sentinel/verifier consolidation reduces autonomous coverage, not just cadence.** Making `sentinel.yml` and `everest-sentinel-5-repos-deploy.yml` dispatch-only per the issue's explicit instruction ("only one carries `schedule:`") means `sentinel.yml`'s patrol script and the five-repo deploy poller no longer run on autopilot — only `sentinel-v2.yml`'s patrol fires on the new canonical schedule. Queued five-repo deploys will sit until manually dispatched. Flagged in `docs/ops/GHA_SCHEDULE_MAP.md` and here per Honesty Protocol; this is exactly what the issue authorized but is a real functional trade-off, not a no-op reschedule.
3. **Not every DB-touching `0 <hour> * * *`-style daily schedule was retimed.** Scope item 3's stated pattern set (`*/5`, `*/10`, `*/15`, `*/30`, `0 * * * *`) was applied literally plus two judgment-call additions (`gold-standard-tick-watcher.yml` at `*/20` since it collides with :00, and `s5-meter-emit.yml` at fixed `:15`) — both DB-touching and cadence-preserving to retime. The ~140 other once/day-at-fixed-hour workflows in this repo were left untouched: they are not part of the issue context's measured stampede contributors and retiming all of them would be a large low-value diff against the K2/K3 surgical-change guidance. Documented as an explicit non-change in `docs/ops/GHA_SCHEDULE_MAP.md` rather than silently skipped.
4. **2-hour post-merge evidence (DoD items 2 and 3) could not be captured synchronously** — GHA scheduled-run cadence and DB restart rate are wall-clock phenomena that cannot be accelerated. A background check (harness task `b6pm0w50v`) was started immediately after push, sleeping 7200s then re-querying both `db_restart_log` and the per-workflow scheduled-run counts for the trailing 2h window. This satisfies the issue's own fallback instruction ("otherwise post it and schedule a follow-up... never self-redispatch") without violating the no-self-redispatch constraint — this is a background shell wait within the same session, not a new dispatch of the issue's lane.
