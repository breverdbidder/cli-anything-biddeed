## Design decisions worth a second look

- **Budget model:** Odoo Community has no Budget app (`account_budget` is Enterprise as
  of ~v13). Built our own minimal `deed.budget.line` (LGPL-3, our code) instead of
  depending on it — see `docs/infra/ODOO.md` licensing section for the full reasoning.
- **Accounting vs. Invoicing:** installed `account` (Invoicing, Community) not the full
  Enterprise Accounting app — flagged as **INFERRED**/needs-confirmation in
  `docs/infra/ODOO.md` since edition-gating specifics weren't verified against a live
  install.
- **`project.project.account_id` field name:** Odoo 18 renamed the old
  `analytic_account_id` to `account_id` (verified against `odoo/odoo` @ 18.0 on GitHub,
  commit 238a41e). Code uses the correct v18 field name.
- **API key minting:** `res.users.apikeys._generate()` is private (leading underscore),
  which Odoo's `execute_kw` blocks by convention — added a one-line public wrapper on
  `res.users` in our own addon rather than trying to call the private method directly.
  This is **INFERRED** design based on documented Odoo API-key semantics (self-service,
  keyed to `env.user`), not verified against a live v18 install this session.
- **`src/lib/odoo.js` not wired into `src/worker.js`:** that file is ~10k lines serving
  live `biddeed.ai` traffic; wiring a call to an unreachable Odoo instance into it now
  would risk breaking real routes for zero benefit until Odoo is actually up. Follow-up
  PR once `deploy-odoo.yml` has run successfully.
