## What was built / fixed

1. **`agents/reel_studio/director_qa.py:review_reel()`** — the diversity check (`check_diversity` → `hook_writer.assert_diversity`) was fed every sibling row for a reel, including non-English translations that copy their EN source's `variant_dna` verbatim (only `lang` differs). This made every reel with a translated variant compare that variant against its own EN source and always find "duplicate archetype" + "Jaccard distance 0.00 < 0.5" — the reason 0/25 variants had ever reached `qa_pass=true` (root cause documented as a HYPOTHESIS in docs/spec/20030.md §"QA diversity-check false-positive on translated pairs"). **CONFIRMED live** against the `broward` reel: variant A (en) and variant A (es) have byte-identical `variant_dna` except the `lang` key. Fix: dedupe siblings by `variant_key` before calling `assert_diversity()`, so diversity is computed once per distinct creative, not once per language copy. Verified in isolation (dedup count 4, `assert_diversity` → `ok=True`) before touching the DB.
2. **`agents/reel_studio/hook_writer.py:fetch_shortlisted_reel()`** — separate, real bug hit while generating new variants: `lib.run_sql()` (Supabase Management API) serializes Postgres `numeric` columns as JSON strings, and `recommend_framing_archetype()` does `assessed_value <= 0`, which raises `TypeError` on a string. Same bug class as the `rank_score` fix already landed in `scripts/biddeed_reels_pipeline.py:494` (#20030) — this was a second, previously-unhit instance of it, in `hook_writer.py`'s own "path of record for NEW reels" (its own docstring's words). Fixed by casting `sold_amount`/`assessed_value`/`delta_pct`/`condition_score` to `float` right after fetch.
3. **`agents/reel_studio/hook_writer.py:generate_variants_for_reel()` / new `fetch_auction_venue_online()`** — `remote_bidder` never appeared in any of the 25 live variants. Not a generation-code defect: it's in `ARCHETYPES` and was eligible for `random.sample()` like any other archetype. Root cause is that `check_archetype_data_match()` hard-rejects `remote_bidder` unless the sale record's own `multi_county_auctions.auction_venue = 'online'`, and **live-verified this session**: `auction_venue` is `NULL` for all 8 render-ready properties in this batch, and for a 1000-row sample of the whole table — a genuine, table-wide upstream data gap (a different lane: the scraper/ingestion side, not Hook Writer/Director QA). Implemented the fix anyway (it's real and correct, and the issue asked for it): `generate_variants_for_reel()` now takes `auction_venue_online: bool | None`, drops `remote_bidder` from the candidate pool when it isn't `True` (mirrors the existing `hidden_value_reveal`-on-premium-sale exclusion), and forces it into one slot (like the data-supported framing archetype already does) when it is `True`. `run_for_county()` now looks this up live before generating. **Currently inert for this batch** because the upstream field is empty — documented here rather than forced dishonestly.

All three fixes pass the existing eval harnesses with no regressions: `python3 agents/reel_studio/hook_writer.py eval` → 42/42 pass (0 fail); `python3 agents/reel_studio/director_qa.py eval` → 50/50 pass (0 fail).
