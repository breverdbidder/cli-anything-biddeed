### Root cause: indian_river letter G

`v_zoning_gold_standard_kpi_v3` for indian_river showed `far_applicable_parcels=1`,
`pk1000_applicable_parcels=1` out of 104 total parcels. Traced to exactly one
parcel: `31391900001598000026.0` (Sebastian, FL), `zone_code='RS-10'`, linked into
`parcel_zones` ~6h earlier by the prior session's letter-I fix. No
`public.zoning_districts` row existed for `(jurisdiction_id=936, code='RS-10')` —
a LEFT JOIN miss. `v_zoning_gold_standard_kpi_v3`'s applicability CTE does
`COALESCE(applicable, true)` on a miss (same documented mechanism as the
`20260827i_gold_standard_pinellas_g_i_regression_flum_backfill.sql` precedent),
forcing this one residential parcel to count as far/pk1000-applicable with no
possible value — 0.0% on both sub-metrics, and G = `LEAST(density, far, pk1000)`
zeroes the whole letter for the entire county.

## Disclosed side effect (Honesty V3 — not hidden)

`gold_standard_certify()` is a **fleet-wide** function, not scoped to this shard's
5 counties. The first of the two `certify()` calls revoked 15 unrelated counties
(bay, desoto, duval, flagler, franklin, glades, gulf, hendry, hernando,
hillsborough, leon, monroe, orange, palm_beach, sarasota, volusia) that were
sitting at `consecutive_non_gold=2` — one non-gold cycle from the N=3 revocation
threshold.

A near-simultaneous sibling architect session (`decision_log` id 3180, issue
#19807/#19818, timestamped 22:35Z — about 2 minutes from this session) had
independently identified this exact same 15-county at-risk set and deliberately
chose **not** to run `gold_standard_loop()`/`certify()` to avoid triggering it,
explicitly hoping another concurrent shard session would do so "naturally." This
session was that other session.

All 15 revoked with reason `adversarial_survival_X_of_10` (X ranging 0–9) — the
same evidence-freshness-decay bug class flagged as systemic in `decision_log` id
3180's `correction_note` (no scheduled process refreshes `ultraloop_audit`
evidence faster than its own 7-day expiry), **not** a new data regression caused
by this session's writes. None of those 15 counties' underlying auction/zoning/
outcome data was touched by this session.

The second `certify()` cycle then newly certified 15 (different) counties as a
side effect of the same fleet cadence (`certified_now=15, revoked_now=0` on cycle
2) — a broadly net-positive but likewise unscoped fleet effect.

No attempt was made to reverse or compensate for the revocations — doing so would
require touching 15 counties' data/evidence with zero session-verified basis for
any of them, itself a scope violation under mandate M5. Flagging plainly instead.

**Recommendation** (not executed — outside this triage's autonomous authority): a
scheduled "freshness refresher" job that re-inserts `survived=true` audit rows for
all-PASS letters on a cadence tighter than 7 days would eliminate this whole class
of collateral revocation fleet-wide — identical to the recommendation
independently reached in `decision_log` id 3180.
