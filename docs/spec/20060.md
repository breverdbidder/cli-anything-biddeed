## Known issue found, not fixed (new finding — surface, don't hide)
`src/worker.js`'s `BD_COUNTY_TW_CSS` constant (a vendored, minified Tailwind
v3.4.17 CSS bundle used on county pages) was already corrupted by an earlier,
broader find-and-replace pass: numerous **unrelated** Tailwind utility classes
(`text-amber-400`, `border-purple-500`, `accent-red-500`, `from-red-500`,
etc.) have had their RGB triples rewritten to the brand blue's RGB, so
semantically distinct status colors (amber/red/purple accents used for badges
elsewhere) now compute as blue. This likely explains the issue's "#0073cf-on-
#10b981" / "#0073cf-on-#3b82f6" badge observations, though neither literal hex
appears in the current source (`#10b981` doesn't appear at all;
`#3b82f6` only appears inside this same constant as Tailwind's genuine,
unmangled `blue-500` — meaning the badges the audit saw are constructed from
a mix of a corrupted utility class and a genuine one). Deliberately **not**
touched in this diff: fixing it correctly requires reconstructing which
classes were originally amber/red/purple vs. genuinely blue, which is not
verifiable from the current file alone, and a second blind regex pass over an
already-corrupted vendored bundle risks compounding the damage. Flagged here
for a follow-up issue with its own investigation budget.
