## What was built

Files touched:
- `.github/workflows/sentinel-v2.yml` — dropped the `workflow_run: workflows: ["*"]`
  trigger entirely. Kept `schedule: '*/5 * * * *'` and `workflow_dispatch`. Job-level
  `if:` guard (skip self/Task Lifecycle/Close Stale on `workflow_run`) left in place as
  defence in depth even though `workflow_run` can no longer fire it.
- `.github/workflows/task-lifecycle.yml` — narrowed `workflow_run: workflows: ["*"]` to
  an explicit 3-name allowlist: `"CC Runner — GHA-only (no Hetzner)"`,
  `"Gemini Runner — T2/T3 grunt lane (no Hetzner, no Claude Code)"`,
  `"SUMMIT: Task from Issue"`. Kept the 30-min `schedule` and the existing `if:` guard.
- `.github/workflows/ci-failure-agent.md` + `.github/workflows/ci-failure-agent.lock.yml`
  — same wildcard, found during the item-5 sweep. Narrowed to an 11-name allowlist
  (8 build/gate/deploy/security workflows + the 3 SUMMIT dispatchers). The `.lock.yml`
  was **hand-patched** (only the `workflow_run.workflows:` list), not regenerated via
  `gh aw compile`, because the installed `gh-aw` CLI (v0.87.10) is far ahead of the
  version that produced the checked-in lock file (`compiler_version: v0.62.5` in its
  header). A real `gh aw compile` run was tried first and produced a ~1900-line diff
  plus an unrelated `.gitattributes` change (dropped `merge=ours` on lock files) — that
  run was reverted (`git checkout --`) as out-of-scope collateral damage, not committed.
  Consequence: `.lock.yml`'s `gh-aw-metadata.frontmatter_hash` comment (line 24) is now
  stale relative to the edited `.md` frontmatter — cosmetic only (it's a compiler
  drift-detection hint, not something GitHub Actions reads at runtime), but the next
  person to touch this file with a matching `gh-aw` CLI version should expect a compile
  diff and review it for unrelated changes before accepting it.

No migrations, no RPCs, no schema changes — this issue was pure workflow-trigger config.
