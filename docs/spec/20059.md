## What was built
Edited `.github/workflows/cc-runner-ghonly.yml`, the "RLS gate (deterministic
— fails on NEW RLS/anon violations vs baseline)" step (was lines 247-267,
now lines 247-291 after the edit):

- Extracted the `curl -X POST .../rpc/rls_gate_check` call into a
  `call_rls_gate()` shell function.
- Wrapped it in a loop over 3 attempts with a `BACKOFFS=(20 40 80)` array.
- After each call, parse the response with the same
  `json.load(...); d.get("passed")` logic as before. Three outcomes:
  - `"true"` → real JSON verdict, pass. Break immediately, no retry.
  - `"false"` (or any other real JSON value, e.g. missing key → `"none"`) →
    real JSON verdict, fail. Break immediately, no retry — mandate item 3
    ("Real violations ... fail immediately, no retry, unchanged").
  - `"error"` (JSON parse failed — covers 5xx/525 HTML bodies, empty curl
    response from timeout/connection reset) → NOT a verdict. Sleep the next
    backoff and retry, up to 3 total attempts.
- After the loop: `PASSED=true` → `rls_gate=passed`, exit 0. `PASSED=error`
  (all 3 attempts non-JSON) → distinct `::error::RLS GATE UNREACHABLE
  (supabase 5xx x3)` message, `rls_gate=unreachable` written to
  `/tmp/cc_rls_gate.txt`, exit 1. Anything else → original `::error::RLS
  GATE FAILED — new RLS/anon violations...` message, `rls_gate=failed`,
  exit 1.
- No changes needed to the "Post run breadcrumb to issue" step — it already
  reads `/tmp/cc_rls_gate.txt` verbatim into the issue comment, so
  `rls_gate=unreachable` surfaces as a distinct breadcrumb value automatically
  (satisfies mandate item 2, "post that distinct breadcrumb to the issue").
