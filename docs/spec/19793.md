```sql

from winnerdata.biddeed_reels br
```

`NULL` `auction_venue` after joining to `multi_county_auctions` on
`case_number`. Per the issue's own data-validity rule, `remote_bidder` is
therefore INVALID for every current row — rendering one would require
either fabricating venue data (explicitly forbidden: "do not guess, do not
default to online") or backfilling `auction_venue` on `multi_county_auctions`
(a separate, out-of-scope data-ingestion task — M5 scope discipline: this
issue names the archetype/validator work, not an `auction_venue` backfill).
This is a genuine data ceiling, not an execution gap — flagged here for a
future dispatch that scopes the `auction_venue` backfill explicitly.
