The issue's own scope note says "home has 2 live occurrences, every /deal page has 1
— verified live Sep 6 15:55 UTC." Investigating *where* those strings come from
surfaced that **home (`/`) is not served by this repo's router** — since the
2026-08-20 strangler cutover (`src/worker.js` `proxyToRadar()` / `RADAR_ORIGIN`),
`/`, `/_next/*`, `/api/*`, and `/radar*` are proxied whole to the Next.js app in the
**`breverdbidder/biddeed-web`** repo. The 2 occurrences on home lived there
(`components/deed-home/LandingSections.tsx`, `components/deed-home/useDeedThread.ts`),
not in `src/worker.js`. GitHub code search (`search/code?q="Shapira Max Bid"`) did not
surface `biddeed-web` at all (likely indexing lag), so this required a direct clone +
grep to find. The 3 deal pages (`/deal/:county/:case`) genuinely are served by this
repo's `src/worker.js`, confirmed correct in the issue body.

## Enforcement added
1. **`factory/gtm/gate.py`** — `RETIRED_PRODUCT_NAME_PHRASES` now includes
   `"Shapira Max Bid"` alongside the existing `"Shapira Analysis"` / `"Shapira Formula"`
   entries (the substring check does not implicitly catch the 3-word phrase from the
   2-word one). This feeds `check_retired_lines_and_product_names`, one of the 14 CMO
   Factory compliance checks run by `factory/gtm/gate.py --paths ...` and by
   `gtm-validate.yml`.
2. **`agents/reel_studio/hook_writer.py`** — `BANNED_TOOL_TERMS` now includes
   `"Shapira Max Bid"`, which feeds `scan_banned_terms()` — called by both
   `hook_writer` itself and `director_qa.check_banned_terms()`, so a reel script or
   caption containing the retired term now fails Director/QA review, not just the
   GTM content gate.
3. **`factory/gtm/fixtures/caption_with_shapira_max_bid.txt`** + a new case in
   `factory/gtm/test_gate_negative.sh`, following the exact pattern of the existing
   `caption_with_s5.txt` / "S5" negative test — proves the check actually fires, not
   just that the string is present in a list.
4. **`.github/workflows/deploy-worker.yml`** — new "SIGNAL$ Max Bid brand check
   (#20058)" step, modeled on #20053's canonical-domain smoke test: curls home + the
   same 3 deal pages named in #20053, fails the deploy if any page still contains
   "Shapira Max Bid" (case-insensitive) or is missing "SIGNAL$ Max Bid".

No `scripts/audit-site.mjs` / `site-audit.yml` exist in this repo (the issue's
suggested file names) — `factory/gtm/gate.py` + `deploy-worker.yml`'s smoke-test step
are this repo's actual equivalent harnesses and were extended in place instead of
