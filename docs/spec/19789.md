## What this session built

### 1. Migrations `20260903f` + `20260903g` (applied live via Management API, same pattern as `scripts/biddeed_reels_lib.py::run_sql`)
- **Live audit first** (per issue instruction, before any DDL): `social_content_queue` = 684 rows, `status` distribution `{pending: 649, draft: 35}`, `target_platform` distribution `{linkedin_personal: 237, telegram: 202, reddit: 125, bigger_pockets: 120}`. No second queue created.
- `social_content_queue` gains `variant_key`/`short_code`/`utm_source`/`utm_content`/`approved_at`/`approved_by`, and its status CHECK constraint gains `pending_approval`/`approved`/`not_configured` (additive — all 5 pre-existing values kept).
- `public.social_quota_ledger`, `public.social_token_health` — new, RLS enabled, no anon/authenticated policy (M2). `social_token_health` seeded with one row per platform, all `NOT_CONFIGURED` (accurate at migration time — no vault credential existed for any of the 5 platforms).
- `winnerdata.reel_links` gains `utm_content`; `public.resolve_reel_link()` updated to return it; new `public.create_platform_short_link()` SECURITY DEFINER RPC (idempotent per `reel_id`+`platform`+`variant_key`).
- **Deviation, found and fixed live in the same session (`20260903g`)**: `create_platform_short_link()`'s first version required `reel_id` (FK to `winnerdata.biddeed_reels`, `NOT NULL`), discovered via a fake-UUID probe before any real row was written. LinkedIn B2B posts are explicitly **not** reel-derived ("LinkedIn is NOT a place for the Bolt grammar" — issue body), so a non-nullable `reel_id` would have made LinkedIn ineligible for its own short code, contradicting the issue's explicit requirement that every platform get "ITS OWN short code." Fixed by dropping the `NOT NULL` constraint and rewriting the idempotency lookup with `IS NOT DISTINCT FROM` (null-safe). Verified live: a `p_reel_id: null` call succeeds and returns a real code; test probe row deleted after confirming.

### 2. `agents/distribution/` — base + 5 adapters
`base.py`'s `PlatformAdapter`/`run()` enforces, for every platform uniformly: NOT_CONFIGURED short-circuit before any queue access, the `approved_at` gate, the `short_code`+`utm_source` attribution gate, and the `social_quota_ledger` cap-check-before-attempt gate. `instagram.py`/`facebook.py`/`tiktok.py`/`x.py`/`linkedin.py` each carry VERIFIED (dated, cited) platform constraints researched live this session against official docs — see `docs/gtm/DISTRIBUTION_LANE.md` for the full findings, most notably:
- Instagram + LinkedIn have **no native draft/private state** — M8 compliance for those two is entirely the `approved_at` gate, no platform-side backstop.
- Facebook (`video_state=DRAFT`) and TikTok (forced `SELF_ONLY` pre-audit) **do** have a platform-side backstop, used as defense-in-depth on top of the gate.
- X retired its free tier Feb 2026 (pay-per-usage, $0.015/post, no scheduling at all) — overturns the issue's own starting assumption. Shipped with `daily_cap_default=0` (policy hold pending Ariel), not a technical NOT_CONFIGURED workaround.
- **Real bug found and fixed live**: `from .base import ...` relative imports fail when a script is invoked directly (`python agents/distribution/instagram.py`) rather than as a module (`python -m agents.distribution.instagram`) — `ImportError: attempted relative import with no known parent package`, reproduced live. Fixed with a `try/except ImportError` fallback to an absolute `from base import ...` in all 5 adapter files, verified both invocation styles now work and exit 0.
- **Real bug found and fixed live**: `PlatformAdapter.record()`'s `campaign_agent_log` write failed 100% of the time — `agent_id text NOT NULL` was never supplied — `23502 null value in column "agent_id"` (caught by the method's own non-fatal `try/except`, so it degraded silently until checked). Fixed by setting `agent_id=f"cmo_factory_distribution_{platform}"`; re-verified live (row landed, then deleted as a smoke-test cleanup).

### 3. `.claude/skills/linkedin-b2b-agent/SKILL.md` + `scripts/linkedin_b2b_agent.py`
Structured per `.claude/rules/skill-authoring.md` (Role/Working Mode/Focus Areas/Quality Gates/Return Format/Guard Rail). `validate_linkedin_draft()` enforces length (900-1300), no banned names, no homeowner-relief framing, no engagement bait, no emoji-bait opener, no vendor/issue-ref names, and — the load-bearing check — every `$`/count figure in the draft must appear in the `evidence` dict computed from a live query this run (a number not traceable to `evidence` fails the draft).

- Draft copy-length tuning: the first pass of `market_pulse` (769 chars) and `data_observation` (827 chars) failed the validator's 900-1300 length check against live data — expanded with additional grounded sentences (still evidence-backed, no new unverifiable claims) until both passed.
