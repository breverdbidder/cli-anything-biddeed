## The structural finding this session adds

`gold_standard_certify()` requires **2 consecutive gold evaluation runs** before `certified` flips true (anti-flap hysteresis, GTM-22C raised revoke to N=2, GTM-22H raised revoke to N=3; the *certify* threshold of 2 consecutive gold runs is unchanged across both). With `consecutive_gold=0` for all 5 shard counties, **no single session — however much engineering effort is spent — can make this literal DoD true**, because even an instantly-perfect 10/10 fix this session would only produce the *first* of the required two consecutive gold runs. A second, later, independent evaluation cycle must also come back gold. This is a design property of the certification gate (correctly preventing a single lucky/noisy pass from certifying a county), not a bug, but it means issue #19806 as DoD-worded cannot be closed by any one dispatch.
