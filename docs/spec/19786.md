## What this session built

### 1. CTA renderer module — `scripts/biddeed_reels_lib.py`
- `SAFE_AREA_X`/`SAFE_AREA_Y` + `assert_in_safe_area()` / `SafeAreaViolation` — hard fail, not a warning, if a bbox exits `x∈[80,1000] y∈[220,1700]`.
- `wrap_caption_lines()` / `dt_wrapped_centered()` — wraps any on-screen caption to ≤2 lines of ≤26 chars, asserts each line's bbox before ffmpeg runs. Replaced the old single-line, unbounded `drawtext` calls for the hook/setup/tension/payoff beats (the exact defect class the issue reported: the payoff caption running off both edges at 24.0s).
- `build_cta_chip_png()` — standalone PNG (Pillow), navy rounded plate, amber URL line (monospace font, see Deviation 1) + white "See this deal →" line, returns its own bbox for the safe-area assert.
- `build_qr_plate_png()` — standalone PNG, ≥260×260 QR with 4-module quiet zone on a white plate + label, returns its own bbox.
- `assemble_video_bolt32()` rewritten: the chip + QR plate PNGs are now overlaid on the **concatenated** output with `enable='between(t,24,32)'`, so both are on screen and readable for the full 24.0–32.0s window (previously: a 1s end-card only). The old 1s inline QR/wordmark overlay is removed.
- `build_bolt32_script_and_caption()`: the loop-line TTS text now speaks the domain once ("...the full breakdown is on biddeed dot A I"), separated from the on-screen `loop_line` text (kept short, safe-area-wrapped).
- `assert_bolt32_spoken_cta()` — DoD negative test (d) for the CTA system.
- `build_bolt32_offvideo_cta()` — caption (first line = bare URL), pinned-comment string, per-platform (instagram/tiktok/youtube/facebook) UTM'd links with `utm_content=<variant_key>`.
- `compute_bolt32_archetype()` — maps (frame_key, phase, condition_tier, days_to_auction) → one of `shock_number | nobody_bid | red_flag_warning | presale_countdown` (S2).

### 2. Director QA — `scripts/biddeed_reels_lib.py` + `scripts/biddeed_reels_pipeline_bolt32.py`
- `extract_frame()` — ffmpeg frame grab at an exact timestamp.
- `assert_ocr_readback()` — tesseract, **cropped to the chip's own known bbox**, 4x upscale, `--psm 6`. Live-reproduced this session: OCR against the *whole* 1080×1920 frame over a busy aerial photo reads grass/tree/roof texture as text and drops or garbles the real chip text (one real frame OCR'd whole-frame as `'Scan for the deal\nae os\n\n'`, losing the URL line entirely) — cropping to the chip's own bbox (already known exactly from `CTA_CHIP_X0/Y0/W/H`) fixed it.
- `assert_qr_decodes_to()` — pyzbar decode, exact-match against the row's `short_url`.
- `assert_url_live()` — shells out to `curl` (not `urllib`) after live-reproducing two failure modes: a bare-UA `urllib` HEAD got 403'd by Cloudflare, and even a browser-UA `urllib` HEAD got 404'd against a URL `curl -I` with the identical UA returns 302 for — a `urllib`/edge quirk, not a real routing problem (see Deviation 3).
- Wired into `process_row_bolt32_cta()`: OCR + QR decode run against the **actual rendered file** at 26.0s and 31.5s before any DB write; a QA failure leaves the row's prior `video_bolt32_url` untouched (never partially overwrites).

### 3. Title + emoji diversity — `scripts/biddeed_reels_lib.py`
- `_BOLT32_POSTSALE_FRAMES` / `_BOLT32_PRESALE_FRAMES` (5 each) / `_BOLT32_EMOJI_PAIRS` (8).
- `generate_bolt32_title_from_frame()`, `assign_batch_diversity()` (round-robins frame per phase, emoji pair across the whole batch), `check_batch_diversity()` (rolling-10-window, ≤2 repeats of either).
- Root-cause fix, not a workaround: the original `generate_bolt32_titles()`/`pick_bolt32_title()` always returns the first-valid candidate, and for any property with a sold price that candidate is deterministically the same frame — this is *why* all 8 shipped reels converged on one frame/emoji pair, and per-row candidate lists alone can't fix a batch-level defect.

### 4. `gen_short_code()` alphabet fix — `scripts/biddeed_reels_lib.py`
- Live-reproduced mid-session: 4 of the first 8 CTA re-renders failed OCR purely because the short code itself contained `0/O`, `1/l/I`, e.g. `'lLbk1m'` OCR'd back as `'ULbk1m'`, `'O2Kt4y'` as `'02Kt4y'` — not a rendering defect, an alphabet defect. `gen_short_code()` now draws from `_BASE_OCR_SAFE` (base62 minus `{0,1,I,i,L,l,O,o}`), shared by every template (v1/v2/presale/bolt32), not bolt32-only.

## Deviations (logged, not silent)

1. **CTA chip URL line uses DejaVu Sans Mono Bold, not the brand Inter font.** Live-reproduced: Inter Bold's `'7'` glyph OCR'd as `'/'` on 2 of 4 real rendered frames even at 3x upscale; the identical string in DejaVu Sans Mono Bold read exactly right at every scale tested. Digits/punctuation in a fixed-width font are less ambiguous to OCR. Only the URL line changed; "See this deal →" stays in the brand font.
2. **"min 64px cap-height" (issue's literal wording) read as a font-SIZE, not a measured cap-height.** DejaVu Sans Mono Bold's actual capital-letter height at font size 64 is ~47px; a true 64px cap-height for a 20-char short URL needs ~88px, which doesn't fit any chip width inside the safe area's 920px budget. INFERRED reading, logged in `build_cta_chip_png()`'s own docstring.
3. **`assert_url_live()` shells out to `curl`, not `urllib`.** Live-reproduced: a `urllib` HEAD against `biddeed.ai` (Cloudflare-fronted) 403'd with a bare UA and 404'd even with a browser-UA header, while `curl -I` against the exact same URL consistently returns a clean 302. Same class of edge/client quirk `storage_upload()` already works around by shelling out to curl instead of urllib.
4. **loop_line's on-screen caption (28-31s) is dropped**, kept only in `beat_map`/spoken TTS. Its beat window sits entirely inside the new 24-32s CTA window, and the two elements' safe-area boxes can't both fit the frame's remaining vertical space (~780px above the QR plate) without colliding. The CTA chip already carries "See this deal →" for that whole window.
5. **`gen_short_code()`'s alphabet change is shared across all templates** (v1/v2/presale/bolt32), not scoped to bolt32/this issue only — the ambiguity is in the short code itself, not any one edit's overlay, so scoping the fix to bolt32 would leave v1/v2/presale rows with the same latent OCR risk.
6. **`process_row_bolt32()` (the pre-existing `--ids` single-row path) also gained the CTA chip/QR plate** (its old `assemble_video_bolt32()` call signature no longer compiled after the rewrite) but does **not** run diversity assignment or the Director QA gate — only `--cta-batch`/`process_row_bolt32_cta()` does. Logged in the skill addendum so a future session doesn't assume `--ids` gets QA coverage.
7. **S3 progressive disclosure's "full report" rung (c) is not built.** The locked-rung UI (named sections, blurred values) is real and live; unlocking it into the actual SIGNAL$ Property Report is a separate, pre-existing report-generation subsystem (`/report/:id`, `/free-report/*`) this session did not touch — wiring the email-gate submit to trigger that report is Residual item 1 below.
8. **S5 (email-sequence memory) is data-plumbing only.** `first_reel_code`/`first_county`/`first_archetype` are captured and available on `lead_profiles`; the actual email-sequence SEND logic (`scripts/winnerdata_ff_digest_lib.py`, `scripts/countdown_reengagement_send.py`, etc.) is a separate, large, already-existing subsystem this session did not modify — Residual item 2 below.
9. **Re-render coverage is 3/8, not 8/8** (see DoD table) — a genuine ElevenLabs credit-quota ceiling hit mid-session (`quota_exceeded`, `6 credits remaining, 8 required`), not a bug or an authorization question. Documented in full under "The quota ceiling" below.

## The quota ceiling (why 5/8 reels are un-re-rendered)

`scripts/biddeed_reels_pipeline_bolt32.py --cta-batch <8 ids>` ran twice this session:

- **Run 1** (original short codes, before the OCR-safe alphabet fix): 3/8 succeeded (`polk`, `martin`, `broward`), 4/8 failed OCR (character-ambiguity defect, fixed after this run), 1/8 hit `HTTP 401` on its ElevenLabs call (the batch's last row, `leon/2024 CA 000670`) — the first sign the account was running low.
- Between runs: rotated all 8 short codes to the OCR-safe alphabet, fixed `assert_ocr_readback()`'s crop/upscale, re-ran.
- **Run 2** (rotated codes): all 8 failed immediately with `HTTP 401`. Direct diagnostic call to `POST /v1/text-to-speech/{voice}` returned:
  ```
  {"detail":{"type":"invalid_request","code":"quota_exceeded",
  "message":"This request exceeds your API key (BidDeed API ) quota of 10000.
  You have 6 credits remaining, while 8 credits are required for this request.",
  "status":"quota_exceeded"}}
  ```
  This is a genuine, non-retriable resource ceiling — confirmed via the provider's own error body, not inferred from an HTTP status code alone.
- **Recovery**: reverted all 8 rows' `short_code`/`short_url` (and the matching `winnerdata.reel_links.code`) back to their exact pre-session values, so the 5 rows that never got a new CTA video stay internally consistent with their still-live, pre-session (non-CTA) `video_bolt32_url`. The 3 rows that DID get a genuine new CTA video (from Run 1, before the code rotation) kept their Run-1 codes, since that's what's actually baked into their rendered chip/QR pixels. Verified via a join query (Evidence below) — no row has a mismatched code/video pair.
- **Residual**: `escambia/2025 CA 001460`, `lee/2026000141`, `leon/2025 CC 003163`, `leon/2024 CA 000670`, `walton/25CA000534` need `python scripts/biddeed_reels_pipeline_bolt32.py --cta-batch <these 5 ids>` re-run once ElevenLabs credits refresh. The code (diversity assignment, safe-area, OCR-safe short codes, QA gate) is fully built and proven on the 3 that succeeded — this is purely a "run it again" residual, not unfinished engineering.
