Precedence: this file > docs/spec/20031.md > issue body > comments. Operating document: docs/gtm/GTM_SOP_v1.md.

## Hard guardrails
1. VIEWS ONLY. No new tables, no ALTER on production tables (Ariel approves schema changes; none are approved here). New views are `WITH (security_invoker=true)`; nothing new is anon-readable; run the RLS gate after DDL.
2. G-SPI stays distinct from the Founder D0 SPI (`spi_gates` / `spi_task_registry` / `spi_daily`). Do not write to `spi_daily`.
3. Attribution is additive, never blocking: a checkout or capture without a reel code must still succeed. No change to Stripe products, prices, or the biddeed-checkout / stripe-webhook activation logic — metadata only.
4. Worker deploys ONLY via push → deploy-worker.yml (never raw Cloudflare API pushes — the Aug 7 outage). biddeed-web deploys via its Cloudflare workflow; biddeed-web main is protected — open a PR.
5. PostHog: use the existing project key; server-side events from the Worker as already done for `report_purchased`. No new analytics vendor.
6. Friday memo posts to the issue/tracking issue only — no Telegram/SMS/Slack (no external channels).
7. SECRETS: names only. PROCESSES: no generic `pkill`; kill by PID/port; never `next start`.
8. Honesty V3: every number in the memo has a source view and a tag; "no rows yet" is a valid, required statement when true.
