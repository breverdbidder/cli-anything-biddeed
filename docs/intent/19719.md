## Standing mandates (copied into every downstream artifact — never comment-only)

- Real re-queried numbers only. A green run that moves zero rows is a failure.
- Login failures are FATAL, never WARN-and-continue. Every harvest run writes provider, run id, county, sale date, rows scheduled, rows with result to a run log.
- Throttle-safe: sequential per platform, backoff, no parallel logins on the same credential set. Automated login lockout (Aug 10) is the known failure mode.
- Credentials from Supabase vault / GitHub secrets only. Never in code, issues, or logs.
- Nothing here changes FF delivery or approval: batches stay `pending_approval`, Ariel approves in the LMS.
- Do NOT touch gold_standard_*, the fixed v_property_card_verified view, or PO rows.
- New tables get RLS.

**realtdm.com is NOT harvested.** Zero source strings reference it. The clerk-SSOT discovery track explicitly *excluded* every `<county>.realtdm.com` as "RealAuction-family, login-gated" (Brevard, Highlands, Sarasota, Washington, Polk, Seminole, Miami-Dade, and more). That was correct for a login-free track; it is wrong for this one. RealTDM is where the tax-deed **file** lives — application, scheduled sale, result, redemption/cancellation — and those counties' TD calendars were downgraded to NO_PUBLIC_CALENDAR precisely because TD routes through it.

**Integrity bug:** rows carry `winning_bidder` with `auction_date` in the future (latest 2026-09-23), and `realauction_bidhistory_modal:<county>:<date>` sources exist whose `updated_at` precedes the sale date in the string. Something writes a "winner" before the sale happens (likely plaintiff max-bid or a placeholder). Every such row is a false third-party sale waiting to become a fake FF.

**Denominator bug:** "held" today counts everything with an auction_date, including cancelled/redeemed. Clerk-SSOT cancellations exist for some counties (`parity_status = CLERK_SSOT_CANCELLED`); RealTDM redemptions do not exist at all.

## Goal metric

**Harvest completeness per county per sale day = rows with a terminal result ÷ (scheduled − confirmed cancelled/redeemed), within 24h of the sale.**
Terminal result = one of: SOLD_THIRD_PARTY (winner name + amount), SOLD_PLAINTIFF, NO_SALE, CANCELLED, REDEEMED.
- Current: ~18% (30-day, both types); 0% in nine of the top-20 county/type cells.
- Target: **≥ 95% within 24h**, all RealAuction-family counties, both sale types.
- Time-to-result also recorded (gavel → row), because it is the numerator of time-to-SIGNAL$.

## What "done" looks like

1. **Measure-first run log.** New table `harvest_runs` (provider, mechanism, county, platform, sale_date, started/finished, login_ok, scheduled, with_result, error). First dispatch step answers, from a real run: is Bright Data Scraping Browser the live mechanism, and did the Phase 1 residential-IP login diagnostic ever pass? Recorded in the log and in `spi_task_registry`, not in a comment.
2. **Daily sweep replaces county-at-a-time backfill.** Every RealAuction-family county × sale type, prior-day sale dates first, then T+1/T+3/T+7 re-checks for late-posted results. Sequential, throttle-safe, one credential set per platform.
3. **realtdm.com added as a third platform.** Per-county `<county>.realtdm.com` login + tax-deed file harvest: scheduled sales, results, redemptions, cancellations. Populates the TD denominator and the TD calendar for the counties the clerk track had to downgrade.
4. **Terminal-result column** on `multi_county_auctions` (`sale_result` enum above) written by every mechanism; `winning_bidder` alone is no longer the completeness signal.
5. **Future-dated winner guard**: constraint or trigger — no `winning_bidder`/`sold_amount` write where `auction_date > now()`; existing violators quarantined and re-harvested.
6. **Completeness view** `v_harvest_completeness` (county × type × sale_date → scheduled, cancelled, with_result, %, median hours-to-result) feeding D0/SPI daily and the D6 watchdog: any county/type cell < 80% for 2 consecutive sale days opens an `spi_gates` row.
7. **Golden set**: 50 sales with known-good results across 10 counties and both platforms; every harvester change must reproduce them before merge.
