## Hard guardrails
1. Tokens never appear in logs, issue comments, PostHog, browser responses, or git. Store in the Supabase vault via service role; read back only through get_vault_secret_mcp from publishing lanes.
2. OAuth `state` is random, single-use, server-checked (CSRF). Redirect URIs exactly as the setup page tells Ariel: `https://lms.winnerdataai.com/connections/{meta|tiktok|x}/callback`.
3. Same auth gate as the rest of the LMS (Cloudflare Access / Basic Auth — whatever is live; do not weaken it). Mobile-first 390 px; Playwright proof; zero console errors.
4. No publishing lanes in this issue. No account creation. No LinkedIn company-page API.
5. Prefer vault + existing `social_token_health`; a new table only if strictly required, RLS on, service-role only, stated in the spec (Ariel approves schema changes).
6. Worker deploys via the LMS repo's existing deploy workflow only — never raw Cloudflare API pushes.
7. If META_APP_ID / TIKTOK_CLIENT_KEY / X_API_KEY are absent, the tiles must render "Not configured — add <secret name>" and the routes must fail closed; do not invent placeholders.
8. SECRETS names only; PROCESSES no generic pkill; kill by PID/port.
